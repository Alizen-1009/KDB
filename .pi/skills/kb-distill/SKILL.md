# Distill：把技术对话沉淀进知识库

## 目标

把当前对话编译为长期可查询的知识，而不是保存聊天流水账。提取定义、机制、数据流、对比、权衡、边界和待核实点，写入最合适的 wiki 或 output 页面。

本 skill 处理“对话中形成了什么知识”；页面 schema 与知识库维护规则仍以 `AGENTS.md` 为准。涉及一份尚未摄入的 raw 资料时，同时读取 `../kb-ingest/SKILL.md` 并遵守它的来源页与硬性 gate 规则。

## 开始前

1. 阅读 `AGENTS.md` 的《写作标准》《编辑原则》《Obsidian 约定》。
2. 阅读 `wiki/index.md`，再按需读取相关 map、概念页、实体页和来源页。
3. 回看当前对话从主题开始处到用户提出沉淀请求为止的完整内容，不要只总结最后一轮。
4. 识别对话依赖的 raw 文件、来源页、代码、报告或外部文档；若涉及 raw 文件且本会话尚未完整读过，必须先读完。

## 第 1 步：提炼，不转录

不要写“用户先问了……然后又问了……”。把对话重组为冷读者可独立理解的知识结构，例如：

- 定义与适用范围
- 核心机制或逐步数据流
- 与相近概念的区别
- 与其他机制的组合关系
- 通信量、性能或工程权衡
- 常见误解与面试口径
- 实现边界和待核实问题

删除寒暄、重复追问、临时措辞和已被后续回答纠正的说法。不要把一次问答原样贴进概念页。

## 第 2 步：给每条结论定级

写入前把材料分为三类，并在文档中保持边界：

1. **来源事实**：raw、已有来源页、官方源码或文档明确陈述；必须能回链。
2. **机制推导 / LLM 归纳**：由来源事实推演出的解释、类比或公式；使用“可以理解为”“粗略估算”“更准确地说”等克制表述，不冒充原文。
3. **待核实**：没有一手来源、依赖版本、任意拓扑支持范围、benchmark 外推或对话中的猜测；显式标注“待核实”。

对话本身不是事实来源。不要仅因为某句话在聊天中出现过，就为它创建来源页或写成确定事实；用户提供的一手经验可标为“用户经验，待外部核实”。

## 第 3 步：选择落点

按内容性质选择最小充分的落盘范围：

- 单一稳定机制：新建或局部更新 `wiki/concepts/<概念>.md`。
- 项目、框架、模型或组织能力：更新 `wiki/entities/<实体>.md`。
- 对一份真实 raw 资料的摘要：按 `kb-ingest` 创建 `wiki/sources/<标题>.md`，必须包含 `原始文件：`。
- 跨多个概念的长篇教学文档或架构分析：创建 `output/reports/<标题>.md`，并把稳定结论局部回填 wiki。
- 面试导向的完整问答：创建 `output/interview/<标题>.md`，并回填稳定概念。
- 仅为下一 session 延续工作：不要使用本 skill，应使用 `handoff`。

不要为了“保存对话”创建虚假的 source 页面，也不要把聊天 transcript 写入 `raw/`。优先局部更新已有页面；只有形成独立、可复用概念时才新建页面。

## 写入授权与 gate

- 用户明确说“写入、保存、回填、沉淀、ingest 到知识库”时，该请求就是对**对话整理**的落盘授权，无需再询问一次。
- 用户只说“总结/整理一下”但未指定落盘时，先给出拟定标题、结构和目标路径，然后停下等待确认。
- 如果任务同时包含一份尚未经过 `kb-ingest` 阶段 1 的新 raw 资料，`kb-ingest` 的“先汇报、等确认”硬性 gate 优先；不得用本规则绕过。
- 如果本会话已经完成 `kb-ingest` 阶段 1，用户后续说“把我们聊的内容整理并 ingest”可视为确认，直接进入落盘。

## 第 4 步：写文档与回填

1. 先读所有目标页面，理解现有结构后做最小编辑。
2. 新建页面时使用对应目录 `_TEMPLATE.md` 和 `AGENTS.md` 固定词表。
3. 长篇报告与概念页分工：报告保留完整论证，概念页只收稳定、结构化、可复用的结论。
4. 来源页、概念页和实体页之间补双向链接；跨目录使用相对 Obsidian wikilink。
5. 数字、版本和硬件配置必须紧邻实验边界；对话中的心算可写为推导公式，但不得伪装成 benchmark。
6. 若新结论与既有页面冲突，保留双方说法及来源，不静默覆盖。
7. 如果新概念改变主题阅读顺序，只编辑 `wiki/maps/<topic>.md` 的《导读》手写区，不编辑自动区。

## 第 5 步：检查与记录

修改 `wiki/` 后依次运行：

```bash
python3 scripts/kb_meta.py sync
python3 scripts/update_index.py
python3 scripts/lint.py
```

lint 必须全绿。然后记录日志：

```bash
python3 scripts/kb_log.py distill "<讨论主题>" \
  -b "整理当前对话为：\`<目标文档路径>\`" \
  -b "依据来源：\`<raw 或 wiki/source 路径>\`" \
  -b "更新概念页：\`wiki/concepts/xxx.md\`" \
  -b "待核实：<没有一手来源的实现细节；没有则写无>"
```

若本次同时正式摄入新 raw 资料，日志 action 使用 `ingest`，并按 `kb-ingest` 的格式记录，不重复追加一条 distill。

## 最终汇报

简洁列出：

- 创建了哪些文档
- 更新了哪些 wiki 页面
- 哪些内容来自原始资料，哪些是机制归纳
- 是否发现冲突
- 仍有哪些待核实点
- sync、index、lint 是否通过

## 不要做

- 不要把对话按时间顺序转录进 wiki。
- 不要把 conversation 或模型回答伪装成 source。
- 不要为了覆盖所有聊天内容而重复已有页面。
- 不要在没有来源边界时推广 benchmark 结论。
- 不要用 `handoff` 代替知识沉淀；handoff 服务于会话续接，本 skill 服务于长期知识。
