# Interview：逐题积累面试题库

## 路径与开始前

仓库根目录为本文件所在目录的 `../../..`；先解析为绝对路径。下文 `AGENTS.md`、`wiki/`、`output/`、`scripts/` 均相对仓库根目录，命令在根目录执行；其他 skill 的链接相对本文件。

先读 `AGENTS.md`、`wiki/index.md`、`wiki/log.md`，遵循《Interview》约束。检查工作区已有修改，保留用户未提交内容。

## 1. 判断本次动作

- **普通提问**：只回答，结束；不写题库、wiki 或日志。
- **只收题**：用户仅提供题目，或说“先记下来，不用回答”，保存题目与已知背景，状态为“待整理”。
- **收录已讨论内容**：将当前对话中已有答案整理成问题页，保留核实边界；指代不明时先确认是哪道题。
- **补答案 / 追问**：定位并完整读取现有问题页后局部更新。用户只说“补充解释”而未要求更新文件时，仍只在对话中回答。
- **系列题单**：逐题查重和收录，另建或更新系列索引；保留用户给定顺序，不擅自扩题或为整批题补答案。

明确收录即为写题库的授权，无需再走一次 ingest 确认。包含个人经历的混合题单中，处理通用技术题，将个人题列为待用户决定的去向；未经另行授权不读写或迁移 `my_resume`。

## 2. 查重与拆题

题库根目录固定为 `output/interview/秋招问题汇总/`：

```text
README.md                  # 总入口，链接全部问题与系列
questions/<问题短标题>.md    # 唯一答案正文
sets/<系列短标题>.md         # 导读与有序问题链接
```

目录按实际写入需要创建。先读已有题库入口，再按标题、关键词、缩写和同义问法搜索 `questions/`、`sets/` 及既有 `output/interview/` 资料；读取命中的相关段落和待修改的完整页面。

- 同一考点、同一适用条件的不同问法合并到原问题页的《其他问法》，保持原文件名稳定。
- 比较题（如“DP 与 TP 有何区别”）本身算一道题；只有能独立提问和作答的不同考点才拆页。
- 硬件、版本或阶段差异改变答案时，保留条件，必要时拆题并互链，不能为了查重抹去区别。
- 原报告已有答案时，新问题页只提炼面试短答并链接原报告具体章节；不复制整段原理正文，也不批量迁移旧资料。
- 追问依赖主问题上下文时留在原页；独立追问另建页后双向链接。

完成标准：每个输入问题都对应“新建 / 更新 / 已存在 / 待确认去向”之一，批次内部也无重复正文。

## 3. 写问题页

文件名用描述性中文短标题，保留必要英文术语，不加日期或流水号；移除路径分隔符及 Obsidian 链接控制字符。先查文件是否存在，避免覆盖。

**只收题用最小结构**，无需建立空的长答案章节：

```markdown
# <完整问题>

- 整理状态：待整理
- 题目出处：<用户本次提供 / 实际题单或资料链接>

## 问题背景
<仅记录用户已给出的条件；没有则省略本节。>
```

有答案时使用以下结构，按实际内容省略可选节，不留下模板占位符：

```markdown
# <完整问题>

- 整理状态：已整理
- 题目出处：<题目的真实出处>

## 其他问法
<可选，同义问法。>

## 30 秒回答
<先结论，再原因和关键边界；一段可口述的答案。>

## 深入解释
<只补理解短答所需的机制、权衡或示例；完整推导链接 wiki 或既有报告。>

## 面试官可能追问
<短追问，或已创建独立问题页的链接。>

## 常见误区
<可选，明确错在哪里及适用边界。>

## 关联知识
<实际存在的 wiki / 报告链接。>

## 参考来源与待核实
<支撑答案的来源、具体章节，以及尚未核实的论断。>
```

“已整理”只表示已有短答和必要解释；部分答案未完成时用“整理中”。事实核实在对应论断旁标记，不因状态改为“已整理”而移除“待核实”。不自动推断用户已掌握。

写答案时先读相关 wiki 页；只有资料不足才查 raw 或外部一手资料。区分来源事实、实现细节、机制推导与待核实内容。实现结论注明版本/commit，性能数字注明配置与来源；没有证据则保留问题或标记待核实。将题目出处和答案依据分开：用户提供的面经能证明题目出现过，不能单独证明答案正确；缺少频率证据时不声称“某公司必考”。

## 4. 维护导航与知识边界

- `README.md` 手工维护全部问题的分组链接与系列入口；整理状态以问题页为准，索引不重复保存状态。
- `sets/` 只写简短导读、范围及有序问题链接；一题可属于多个系列，答案只在问题页维护。
- 问题页链接相关系列，系列页链接总入口；从 README 能到达每道题。
- Vault 内使用真实存在的 Wiki Links，优先写从当前文件出发的相对路径以消除同名歧义。例如 questions 页链接概念可用 `[[../../../../wiki/concepts/FlashAttention|FlashAttention]]`（仅在目标存在时）。
- 首次收题时读取并局部更新仓库的 `output/README.md`，增加题库 README 入口。当前总索引脚本仅列出 `output/interview/` 直属文件，不能假定嵌套题库会自动出现在《面试备考》清单中；通过 Output 入口保证可达，不为此修改生成脚本。
- 收题本身不要求创建概念页或来源页。若用户另要完整研究报告、正式来源摄入或对话知识沉淀，分别读取 [kb-query](../kb-query/SKILL.md)、[kb-ingest](../kb-ingest/SKILL.md)、[kb-distill](../kb-distill/SKILL.md)，遵循其授权和证据流程。
- 用户要求复习卡时读取 [kb-cards](../kb-cards/SKILL.md)，只从合格答案选料；待整理的题目与待核实结论不出卡。

## 5. 验证与收尾

逐项检查：输入题目无遗漏、同义题无重复页、题干条件保留、答案与核实状态一致、内部链接目标及章节存在、入口覆盖本次所有问题。重新执行相同收录请求应复用页面；若无实质变化，汇报“已收录”并结束，不追加空日志。

有实际文件变更时，用现有日志脚本记录本批次一次，再按仓库约定依次刷新和检查：

```bash
python3 scripts/kb_log.py interview "<本次题目或系列标题>" \
  -b '新建/更新：<实际问题页和系列页路径>' \
  -b '待整理/待核实：<实际未完成内容，没有则写无>'
python3 scripts/kb_meta.py sync
python3 scripts/update_index.py
python3 scripts/lint.py
```

最后检查 diff，区分本次变更和原有工作区问题。lint 不替代手工核对题库覆盖与链接；检查失败时如实报告，不顺手修复无关内容。

向用户简短汇报：新增几题、更新几题、复用了哪些已有题、入口路径，以及待整理/待核实或需确认去向的内容。
