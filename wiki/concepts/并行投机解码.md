# 并行投机解码

## 定义

并行投机解码是 [[Speculative Decoding]] 的一种 drafter 路线：不用较小模型自回归地逐 token 生成完整草稿，而是让 diffusion-style 或 masked-filling drafter 在一次或少数几次计算中并行预测多个未来位置，再由 causal target model 验证候选前缀。

“并行”主要发生在 **draft proposal** 阶段；最终输出仍受 target model 的验证和接受规则约束，并不意味着主模型直接变成非自回归生成。

## 它解决什么问题

- 降低 sequential drafter 生成 `k` 个候选时自身的串行延迟。
- 提高单轮可提供给 target verification 的候选数量。
- 在 target model 适合小 chunk 并行验证时，把逐 token decode 的部分串行步骤压缩到更少轮次。

## 核心机制

```text
Causal target prefix
  → target hidden / anchor
  → parallel drafter 同时预测多个 future positions
  → 可选：confidence 与验证长度筛选
  → target 对候选前缀做 causal verification
  → 连续接受到第一个失败位置
  → 保留接受 token，拒绝后缀并继续下一轮
```

- [[DFlash]] 代表固定或预设长度的 diffusion-style parallel draft，并用 target hidden states 增强候选质量。
- [[DSpark]] 在并行 block 后增加顺序建模和 confidence，再根据硬件吞吐曲线动态选择真正进入验证的前缀长度。
- Target verification 仍常把普通 decode 的 `qlen=1` 变成一个小 `qlen=k` chunk，并处理 speculative KV slots、接受提交和拒绝回滚。

## 与传统 drafter 的区别

| 维度 | Sequential drafter | Parallel drafter |
| --- | --- | --- |
| 候选生成 | `y1 → y2 → ... → yk` | 多个未来位置同时预测 |
| draft latency | 随 draft length 形成串行链 | 更偏一次 block 计算 |
| token 依赖建模 | 自回归依赖天然明确 | 需要 masked/diffusion 表示或额外顺序模块 |
| 长后缀质量 | 通常逐步衰减 | 同样可能衰减，且位置间一致性更难 |
| 主要系统难点 | 小模型 launch、KV、串行开销 | target context 注入、置信度、动态验证长度 |

## 与 MTP 的关系

[[Multi-Token Prediction]] / [[MTP Drafter]] 也能一次产生多个未来位置的预测，但实现不一定等同于 diffusion-style parallel drafter：MTP 可以是多个预测头、顺序 MTP module 或与 target 深度耦合的轻量 drafter。分类时应看候选是否在一个非自回归/并行 proposal block 中联合产生，而不是只看“单轮预测多个 token”。

## 关键权衡

- Draft block 越长，理论上单轮可能前进更多 token，但后缀接受率下降会增加无效 draft 与 target verification 计算。
- Parallel drafter 计算更规整，却可能需要额外训练、target hidden extraction、跨层融合和专用 runtime。
- 高并发下，验证 token 数会改变 target batch shape；单请求最优 draft length 不一定等于整个 batch 的吞吐最优长度。
- 固定长度实现简单；自适应长度可减少浪费，但依赖 confidence 校准和可靠的硬件性能模型。
- 正确 verification 的目标是保持 target 生成语义；benchmark 中的质量变化应先区分算法近似、数值非确定性和样本噪声。
