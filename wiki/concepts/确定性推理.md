# 确定性推理

## 定义

在相同模型、相同输入、相同配置下，尽量让推理过程稳定地产生相同输出的运行方式；它既涉及采样策略，也涉及底层 kernel、调度和数值执行路径是否可复现。

## 它解决什么问题

- 满足 `debug`、`精度对齐`、`回归测试`、`RL rollout` 等场景对可复现性的要求
- 帮助区分“模型本身行为变化”与“系统执行路径变化”带来的输出差异

## 核心机制

- 先区分两类不确定性：`采样随机性` 与 `计算非确定性`
- 对采样侧，可通过固定 `seed` 或改用贪婪采样来约束随机性
- 对计算侧，需要进一步约束 batch 形态、kernel 选择、tiling 策略和规约顺序，避免同一请求在不同执行路径上出现不同数值结果
- 在推理框架中，这通常意味着要限制 `dynamic batching / continuous batching / multiprocessing` 带来的调度差异，并启用确定性 kernel 或 batch-invariant 路径
- DFlash/DSpark 的来源实测提供了一个 batch-dependent 案例：文章称同一 Baseline 在 temperature=0 下两次 GSM8K 评测相差 `5.2pp`，并归因于不同 batch 组合改变浮点规约顺序，进而影响边界 token 的 argmax。该解释符合机制方向，但缺少逐 token 数值追踪，应视为来源归因而非已完成根因证明。

## 关键权衡

- 能提升可调试性、可比性和训练闭环中的稳定性
- 往往会牺牲部分吞吐、并发度或 kernel 优化空间
- 真实可复现性通常不是“只设一个 seed”就能获得，而是系统层多项约束共同作用的结果
