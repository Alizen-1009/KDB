# 混合注意力

## 定义

在不同层交替使用不同注意力/序列建模机制，以兼顾效率和全局依赖能力。已有页面最初覆盖 sliding/full attention；新的 SGLang KDA 来源补充了另一种形态：MLA full-attention 层与 KDA/GDN 递归线性注意力层交错。

## 它解决什么问题

- 避免所有层都使用 full attention 带来的高昂成本
- 同时保留周期性的全局信息交换能力

## 核心机制

- 大部分层采用 sliding attention 处理局部上下文
- 周期性插入 full attention 层捕捉全局依赖
- 通过层职责分工达到更好的长上下文计算平衡
- MLA/KDA 混合模型还要维护两类状态：MLA 层使用按 token 增长的 KV Cache；KDA/GDN 层使用按请求、按层固定大小的 Conv State 与矩阵状态
- Runtime 必须协调 Token KV Pool 与递归状态池，Prefix Cache 则只能在两类状态都可恢复的边界复用

## Qwen3.8-Flash-Next 的混合方式

- [[../entities/Qwen3.8-Flash-Next]] 每四层采用 `3` 层 GDN 加 `1` 层 global full attention：GDN 用不随上下文长度增长的递归状态压缩前缀，global attention 保留直接 token-level retrieval，但仍承担二次 attention 计算与随 token 增长的 KV Cache。
- 在 `256K` CPT 阶段，backbone 与 MTP 的所有 global full-attention 层替换为 [[Qwen Sparse Attention|QSA]]；因此其最终长上下文路径应理解为 `3 GDN + 1 QSA`，而不是把所有层改成固定状态递归层。
- `28` 层 `25B-A3B`、`400B` tokens@`4K` 加 `80B` tokens@`32K` 的消融中，full attention / SWA hybrid / GDN hybrid 九项平均分为 `49.87 / 51.15 / 53.81`；GDN 胜 full attention `8/9`、胜 SWA `7/9`。这是指定模型与训练配方的结果，不能推出任意 hybrid 比例都更优。

## GLM-5.3-Flash 的混合方式

- [[../entities/GLM-5.3-Flash]] 的 `45` 个文本层由 `34` 个 [[KDA]] 层和 `11` 个 [[DeepSeek Sparse Attention|DSA]] 层组成，约 `3:1`；DSA 位于 layers `3/7/.../43`，最后的 layer `44` 为 KDA。
- KDA 维护固定大小 recurrent state，负责低成本持续聚合；DSA 显式检索 top-`2048` 历史 token，补足精确长程访问能力。
- 配置中的 `full_attn_layers` 是通用字段名，实际 `layer_types` 为 `deepseek_sparse_attention`，不能解释为普通 dense full attention。
- Flash 没有 GLM-5.2 的跨层 [[IndexShare]]，但保留 MTP iterations 间的 index sharing。

## 关键权衡

- 局部层更高效，但全局建模能力有限
- 全局层补足长程依赖，但会带来更高计算开销
