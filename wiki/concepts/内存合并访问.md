# 内存合并访问

## 定义

对于同一条内存指令，硬件将一个 warp 内活跃线程的 global memory 地址请求合并为尽量少的内存事务；访问覆盖的对齐区间越少，通常越高效。

## 它解决什么问题

- 降低 DRAM 访问开销
- 减少因访存模式离散而带来的带宽浪费

## 核心机制

- Warp 中线程按更连续、更对齐的地址模式访问内存
- 让一次 burst 尽可能服务更多线程的数据需求
- 在矩阵乘法和张量变换里，线程布局与数据布局要一起设计
- 对 compute capability 6.0 及以上设备，普通 global memory 合并访问按覆盖的对齐 `32B` 区间计数；32 个活跃线程各读一个连续 `float`，起点按 32B 对齐时需要 4 个区间。不能把 `128B cache line` 与单个内存事务直接等同。
- 一个实用判断法是把 `threadIdx.x = 0..31` 代入地址表达式，检查相邻线程地址差是否接近 `sizeof(T)` 且首地址对齐；若步长变成 `N * sizeof(T)`，往往说明访问开始发散
- 典型反模式包括 `A[threadIdx.x * N + threadIdx.y]` 这类跨行步进访问，以及 `AoS` 里只取单字段导致的跨结构体跨步读取；常见修复是换线程映射、重排布局或改成 `SoA`

## 关键权衡

- 连续对齐的访存通常更快
- 一旦维度、padding 或线程映射不合适，就可能破坏 coalescing
- 读路径和写路径经过的缓存层未必完全一致，但判断 coalescing 的核心仍是“事务数是否被压低”

## 官方文档校准：Cache line 与 Sector

- NVIDIA Nsight Compute 文档描述的 L1/L2 cache line 为 128B，分为 4 个 32B sector；这是缓存组织粒度，不能据此推断一次读取必然从显存搬入整条 128B。
- 合并访问关注同一 warp、同一条指令的地址分布；缓存命中关注所需 sector 是否已驻留。Sector 请求量不等于实际 DRAM 流量。
- 旧版资料将 128B line 与 transaction 合写的经验表述不宜直接用于现代设备；分析时明确架构、缓存层级与指令。
