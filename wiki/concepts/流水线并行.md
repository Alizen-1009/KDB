# 流水线并行

## 定义

按网络深度把模型切成多个 stage，并通过 micro-batch 在这些 stage 间流水传递激活与梯度的模型并行方式。

## 它解决什么问题

- 让单个模型跨多个设备分布存放，从而解决单卡放不下的问题
- 在跨节点链路较慢时，用激活点对点通信换取更好的参数内存扩展

## 核心机制

- 沿层深切分模型
- 使用 micro-batch 减少 stage 间 idle 时间
- 通过 pipeline schedule 降低 bubble，提高利用率
- 在最小代码骨架里，stage 间常直接体现为 `send / recv` 传递激活

## 关键权衡

- 内存扩展好，跨慢链路时通信形态也相对友好
- 但存在 bubble，对 batch size 和 micro-batch 选择非常敏感

## 研究备注

- 后续可补 1F1B、zero-bubble pipeline 和 interleaved schedule 的差异
- `mHC` 论文给了一个更贴近大模型训练栈的例子：它把重计算块与 pipeline stage 边界对齐，并在 `DualPipe` 调度里刻意做通信与计算重叠
- `Attention Residuals` 论文线则给了另一种系统案例：通过 cache-based pipeline communication 传递历史 block 表示，并结合 two-phase computation，把 block 级跨层聚合尽量压缩成可落地的训练开销
- 论文本体更具体地指出：在 interleaved pipeline schedule 下，如果每次 stage transition 都传完整历史 block，会产生重复通信；cross-stage caching 让后续 virtual stage 只传增量 block，把峰值 transition 成本从随总 chunk 数增长压到随 physical stage 数增长
