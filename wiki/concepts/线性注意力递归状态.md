# 线性注意力递归状态

## 定义

线性注意力递归状态是 GDN、KDA 等递归线性注意力层在自回归推理中跨 token 持久化的固定大小状态。常见实现包含两种职责不同的状态：

```text
每个请求、每个线性注意力层
├── Conv State：短期 causal depthwise convolution 窗口
└── Recurrent Matrix State：长期压缩记忆
```

二者都不随上下文长度线性增长，但缺少任意一个都通常不能从某个前缀边界正确继续推理。

## Conv State

### 用来做什么

Conv State 为下一 token 的短 causal depthwise convolution 提供最近若干位置的输入特征。若卷积核大小为 `K`，当前卷积输出需要当前特征与最近 `K-1` 个历史特征：

```text
c_t = Σ_{i=0..K-1} w_i ⊙ x_{t-i}
```

其中 `⊙` 表示逐通道运算。逐 token decode 时不会重新计算历史，因此状态保存：

```text
ConvState_{t-1} = [x_{t-K+1}, ..., x_{t-1}]
```

当前 `x_t` 到来后，先与该窗口共同计算卷积，再丢弃最老元素并写入 `x_t`。这里的 `x` 通常是进入 depthwise conv 的投影后特征，而非原始 token 或完整 hidden state；究竟是拼接投影还是某些 q/k/v 分支依赖模型实现。

### 为什么不能只保存矩阵状态

长期矩阵状态压缩了历史关联，却通常无法还原最近 `K-1` 个卷积输入。即使恢复了正确的 `S_t`，缺少 Conv State 仍会让下一 token 的卷积输出以及后续 q/k/v 错误。因此一个可继续执行的 checkpoint 通常同时需要 `ConvState_t` 和 `S_t`。

## Recurrent Matrix State

### 用来做什么

矩阵状态把全部历史逐步压缩成固定大小的 key-to-value 关联记忆。标准 attention 显式保存：

```text
K_history: [T, d_k]
V_history: [T, d_v]
```

递归线性注意力则维护每个 head 的矩阵：

```text
S_t: [d_k, d_v]        # 或转置布局 [d_v, d_k]
o_t = q_t^T S_t        # 读取历史压缩记忆
```

包含请求槽和 heads 时，运行时形状常类似：

```text
[num_sequences, num_heads, d_k, d_v]
```

它不是 token 列表，而是 `S_0 -> S_1 -> ... -> S_t` 的递推最终结果。不同层、不同请求各有自己的状态；启用 TP 后，每个 rank 通常只保存所负责 head/shard 的部分。

## GDN 如何更新矩阵状态

GDN（Gated DeltaNet）的简化机制可以理解为在线修正 key-to-value 映射。当前 token 从 hidden/projection/conv 路径产生：

- `q_t`：从状态读取；
- `k_t`：决定写入方向；
- `v_t`：希望写入的内容；
- `alpha_t` 或 gate：控制旧状态衰减；
- `beta_t`：控制当前写入强度。

当前 FLA/vLLM 常见 gate 参数化为：

```text
dt_t    = softplus(a_t + dt_bias)
g_t     = -exp(A_log) * dt_t       # log-space decay，<= 0
alpha_t = exp(g_t)                  # real-space retention，(0, 1]
beta_t  = sigmoid(b_t)              # delta write gate，(0, 1)
```

其中 `A_log [H]` 与 `dt_bias [H]` 是每个 value/state head 的可学习参数：`A_log=log(lambda)`，实际连续衰减系数构造成 `A=-exp(A_log)<0`，保证 retention 不超过1；`dt_bias` 是有效步长 `dt` 的head-wise基线，token投影 `a_t` 在其上做动态调整。`A_log` 越大通常遗忘越快，`dt_bias+a_t` 越大则当前token的有效步长越大、衰减越强。

采用状态布局 `S [d_k,d_v]`，逐 token 递推为：

```text
S_bar      = alpha_t * S_{t-1}
prediction = k_t^T S_bar
error      = v_t - prediction
delta_v    = beta_t * error
S_t        = S_bar + k_t delta_v^T
o_t        = (q_t * scale)^T S_t
```

完整状态更新：

```text
S_t = alpha_t S_{t-1}
    + beta_t k_t (v_t - k_t^T alpha_t S_{t-1})^T
```

具体实现可能把状态转置保存为 `[d_v,d_k]`，于是预测写成 `state @ k`、更新写成 `delta_v ⊗ k`；数学等价。FLA reference使用read-after-write。核心是：先让衰减后的旧记忆预测当前 value，再只沿当前 key 方向写入预测误差。`delta` 指这个修正量；`gated` 同时包含旧状态遗忘 `alpha` 和当前写入强度 `beta`。

逐步公式、形状、数值例子与PyTorch伪代码见 [[../../output/reports/GDN公式与逐步计算|GDN公式与逐步计算]]。

## Qwen3.8-Flash-Next 的 GDN 参数化

[[../entities/Qwen3.8-Flash-Next]] 的 GDN 对 q/k/v 投影后分别做短 causal depthwise convolution，q/k 再做 L2 normalization；decay/write gate 沿用数据相关 `α_t/β_t` 递推。其输出采用 bounded sigmoid gate 调制 zero-centered RMSNorm 后的 recurrent output，而不是原始 GDN 的 SiLU output gate。

在混合主干中，每四层有三层 GDN、一层 global attention：GDN 的 recurrent state 固定大小，但 global 层仍保留随上下文增长的 KV Cache。论文只在 NVIDIA GPUs 多个设置下报告 FlashQLA 相对 FLA Triton kernel 的 forward `2–3×`、backward 约 `2×`，不能泛化到其它硬件、shape 或端到端训练。

## Conv State 与矩阵状态如何协作

```text
当前投影特征 + ConvState_{t-1}
    -> causal conv
    -> 当前 q_t / k_t / v_t 等特征

k_t / v_t / gates + S_{t-1}
    -> 更新长期矩阵 S_t

q_t + S_t
    -> 读取历史信息并形成当前输出
```

因此：

- Conv State 是最近若干 token 的短期局部工作记忆；
- Matrix State 是从序列开头到当前 token 的长期压缩记忆；
- Conv State 会通过影响当前 q/k/v，间接影响矩阵状态的读写。

## Prefill 与 Decode

- Decode 每次处理一个 token，原地推进 Conv State 与 Matrix State。
- Prefill 若严格逐 token 递推会形成长依赖链，[[Chunked Gated Delta Rule]] 将时间维切块，块内矩阵化并行、块间传最终 state，最后仍产出可供 decode 使用的 Conv State 和 Matrix State。

## KDA 与 GDN 的边界

从 serving runtime 看，KDA 与 GDN 都属于“按请求、按层维护 Conv State + 固定大小递归状态”的模型，因此可以共享状态槽和 checkpoint 类基础设施。Kimi K3官方报告现已明确KDA状态同样是key-value关联矩阵 `S [d_k,d_v]`，并保留Delta Rule误差写入；核心差异是遗忘门粒度：

- GDN：`S_bar=alpha_t S`，`alpha_t`通常是per-head scalar；
- KDA：`S_bar=Diag(alpha_t)S`，`alpha_t[d_k]`是per-key-channel vector；
- Kimi K3 KDA又将log-decay限制到`(g_min,0)`、`g_min=-5`，以稳定chunk rescaling并统一Tensor Core tile路径。

因此KDA不是严格“逆协方差矩阵”算法；其状态仍是key-to-value fast-weight matrix。详细对比见 [[KDA]] 与 [[../../output/reports/KDA相对GDN的改进|KDA相对GDN的改进]]。

## 与 TTT Layer 的关系

[[TTT Layer]] 也把历史压进固定大小状态，但将状态解释为 learner 权重，并通过自监督损失的梯度步骤更新。原论文定理 1 说明：当 learner 为线性模型、使用 batch GD、`η=1/2`、`W_0=0`，并采用特定 `θ_K / θ_V / θ_Q` 视图时，TTT-Linear 等价于最简 linear attention fast-weight recurrence。

这个等价只适用于严格特例。实际 TTT-Linear 使用 mini-batch、LayerNorm、残差、可学习初始化和学习率；GDN/KDA 又使用 gated/delta 结构化更新和 Conv State。因此三者可以共享“矩阵状态压缩历史”的视角，但不能视为同一算法。

## 关键权衡

- 优点：状态大小不随上下文长度线性增长，长上下文显存占用更稳定。
- 代价：历史被压缩后不能像逐 token KV 一样任意回退，前缀复用需要额外 checkpoint。
- 固定大小不代表状态很小：每请求、每层、每 head 的 `d_k × d_v` 矩阵仍可能占用大量显存。
- Conv State 与 Matrix State 的更新正确性会受 speculative token 回滚、请求迁移、TP 分片与 checkpoint 生命周期影响。

## 面试口径

一句话：GDN/KDA 的 Conv State 保存最近几个投影特征，供下一步短因果卷积使用；矩阵状态保存整段历史压缩出的长期 key-value 关联，当前 token 用 k/v/gate 更新它、用 q 读取它。
