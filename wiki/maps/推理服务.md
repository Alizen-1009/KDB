# 推理服务

## 导读

按“一个请求怎么被调度”读：

1. [[../concepts/Continuous Batching|Continuous Batching]] —— 现代 serving 的地基。
2. [[../concepts/Chunked Prefill|Chunked Prefill]] —— 长 prefill 不再阻塞 decode。
3. [[../concepts/PD分离|PD分离]] —— 按请求阶段拆 Prefill 与 Decode。
4. [[../concepts/可插拔 Decode 引擎|可插拔 Decode 引擎]] —— PD 进一步允许共享 vLLM Prefill，同时把不同流量交给 native 或 TileRT 等专用 Decode backend。
5. [[../concepts/Attention-FFN 分离|Attention-FFN 分离]] —— 再看如何按每层算子角色拆 Attention 与 MoE/FFN；它可与 PD 分离叠加。
6. [[../concepts/Wide Expert Parallelism|Wide Expert Parallelism]] —— DeepSeek/MLA serving 中用 Attention DP + 宽 EP；它也解释了为什么 PD 分离能隔离整个 EP group 的 Prefill 干扰。
7. [[../concepts/vLLM V1 统一调度器|vLLM V1 统一调度器]] + [[../concepts/持久批处理|持久批处理]] —— 具体实现里调度状态怎么复用。
8. [[../concepts/SGLang 与 vLLM 对比|SGLang 与 vLLM 对比]] —— 两套设计的权衡对照。

[[../concepts/Constrained Decoding|Constrained Decoding]] 和 [[../concepts/LLM Programs|LLM Programs]] 是上层接口，[[../concepts/确定性推理|确定性推理]] 是横切关注点（它同时涉及采样、kernel 和调度）。
