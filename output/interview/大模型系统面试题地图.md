# 大模型系统面试题地图

## 说明

这份文档针对一组偏 `AI Infra / 训练系统 / 推理系统 / 集群平台` 的面试题单做结构化整理。目标不是把每题都展开成标准答案，而是先建立一张“知识地图”：

- 这些题到底在考什么
- 哪些题是同一条主线的不同问法
- 现有 wiki 已经能支撑哪些回答
- 哪些部分仍需要后续单独补专题

## 1. 先看这份题单在考什么

这组题其实不是 30 多个离散问题，而是 5 条主线。

### 1. 硬件与性能模型

代表题：

- `FLOPS / TFLOPS / 内存带宽 / 屋顶线模型`
- `GPU 利用率只有 30%，可能原因有哪些`
- `FlashAttention-2 / FlashDecoding 为什么快`
- `GPU 集群算力利用率、掉卡率、功耗如何监控`

这一类在考你：

- 会不会区分 `compute-bound` 和 `memory-bound`
- 会不会把指标和现象挂到同一个性能模型上
- 会不会从 profiler / dashboard 反推出瓶颈位置

### 2. 分布式训练与内存账本

代表题：

- `3D 并行（DP/TP/PP）分别解决什么问题`
- `ZeRO-1/2/3/Offload 的原理和内存节省公式`
- `DDP / torchrun 启动流程`
- `NCCL failed 怎么排查`
- `global batch / micro batch / TP=8, PP=4, DP=2 的关系`
- `如何在 8 卡上训练 175B`

这一类在考你：

- 知不知道每种并行是在切哪一个维度
- 知不知道通信原语对应什么并行方式
- 知不知道训练 OOM、网络故障、启动问题背后的系统原因

### 3. 推理系统与服务编排

代表题：

- `PagedAttention`
- `连续批处理 vs 传统批处理`
- `KV Cache 管理`
- `如何把 130B 推理延迟从 2s 降到 80ms`
- `vLLM / TGI / TensorRT-LLM / SGLang 的区别`
- `Speculative Decoding`

这一类在考你：

- 会不会把推理拆成 `prefill / decode / memory / scheduler`
- 会不会从 TTFT、ITL、throughput、显存碎片四个指标一起看
- 会不会把具体框架差异讲到“数据结构 + 调度策略 + kernel”层

### 4. 模型系统扩展问题

代表题：

- `MoE 为什么更容易 OOM`
- `EP / all-to-all`
- `量化：FP8 / INT8 / AWQ / GPTQ / SmoothQuant`
- `2×24G 怎么跑 70B`

这一类在考你：

- 知不知道大模型“能不能放下、能不能跑起来、能不能跑快”的区别
- 知不知道参数量、激活、KV cache、路由、量化误差、带宽之间的 tradeoff

### 5. 集群平台与工程管理

代表题：

- `1000 张 H100 常见网络拓扑`
- `Slurm + Pyxis + Enroot`
- `为什么 K8s 也开始用于大模型公司`
- `如何设计万卡集群`
- `技术债、技术选型、团队分歧`

这一类在考你：

- 你是不是只会模型系统，不会平台系统
- 你有没有从“单作业视角”升级到“平台资源编排视角”
- 你能不能从技术细节上升到工程判断和团队协作

## 2. 这份题单的高频主线是什么

如果把它压缩成一句话，其实是在问：

> 你能不能把“单卡性能 -> 多卡训练 -> 在线推理 -> 集群平台”串成一条完整系统链。

所以真正值得优先准备的，不是 30 多个孤立问题，而是下面 8 个母题。

### 1. 如何判断一个问题是算力瓶颈还是带宽瓶颈

核心关键词：

- `FLOPS`
- `bandwidth`
- `arithmetic intensity`
- `Roofline`
- `FlashAttention`

这是几乎所有性能题的总开关。

### 2. 训练并行到底是在切什么

核心关键词：

- `DP`：切 batch
- `TP`：切层内张量
- `PP`：切层深
- `ZeRO/FSDP`：切状态

这是所有“3D 并行 + ZeRO + DDP + 启动脚本”题的底层骨架。

### 3. 推理为什么和训练不一样

核心关键词：

- `Prefill compute-bound`
- `Decode memory-bound`
- `KV Cache`
- `Continuous Batching`
- `PagedAttention`

这是所有 vLLM / TGI / TensorRT-LLM / PagedAttention / 动态批处理题的共同背景。

### 4. 内存账本怎么拆

核心关键词：

- 参数
- 梯度
- optimizer state
- 激活
- KV cache

这决定你能不能回答：

- `ZeRO 内存节省`
- `Transformer 显存公式`
- `MoE 为什么更容易 OOM`
- `2×24G 跑 70B`

### 5. 通信为什么会成为系统上限

核心关键词：

- `all_reduce`
- `reduce_scatter`
- `all_gather`
- `all-to-all`
- `NCCL`

这条线串起：

- `TP`
- `DDP`
- `MoE/EP`
- `Ring AllReduce`
- `NCCL failed`

### 6. 推理优化为什么不只是 kernel 优化

核心关键词：

- `scheduler`
- `cache layout`
- `prefix reuse`
- `prefill/decode split`
- `speculative decoding`

这条线决定你回答推理问题时不会只停留在“FlashAttention 更快”这种单点结论。

### 7. 集群平台最怕什么

核心关键词：

- 拓扑不匹配
- 资源碎片
- 容器 / 运行时不一致
- 监控不可观测
- 网络与调度策略错配

### 8. 工程面为什么会问技术选型和团队协作

因为系统岗位最终不是只写 kernel，而是要在：

- 新技术收益
- 旧系统稳定性
- 可观测性
- 团队维护成本

之间做判断。

## 5. 每一类题推荐怎么答

### 1. 概念机制题

适用：

- `PagedAttention`
- `Continuous Batching`
- `FlashAttention`
- `Speculative Decoding`

答题模板：

1. 先说它解决什么痛点
2. 再说核心数据结构或执行流程
3. 最后说代价和适用边界

### 2. 系统对比题

适用：

- `vLLM vs TGI vs TensorRT-LLM vs SGLang`
- `传统 batching vs 连续 batching`
- `PD 解耦 vs PD 分离`

答题模板：

1. 先给比较维度
2. 再说各自最强项
3. 最后说适用场景，不要追求“一刀切最好”

### 3. 内存账本题

适用：

- `ZeRO`
- `Transformer 显存公式`
- `MoE OOM`
- `2×24G 跑 70B`

答题模板：

1. 先拆成参数 / 梯度 / optimizer / 激活 / KV cache
2. 再说哪个是主导项
3. 最后说对应的优化抓手

### 4. 故障排查题

适用：

- `NCCL failed`
- `GPU 利用率 30%`
- `master_port 冲突`

答题模板：

1. 先按层次分桶：启动层、通信层、算子层、数据层、资源层
2. 再给观测指标
3. 最后给最小化复现实验

### 5. 架构设计题

适用：

- `130B 推理降到 80ms`
- `万卡集群设计`
- `8 卡训 175B`

答题模板：

1. 先明确目标函数：时延、吞吐、成本、稳定性
2. 再从模型层、kernel 层、运行时层、集群层分层给方案
3. 最后给 tradeoff 和 rollout 风险

## 6. 这份题单里最容易被混淆的几组概念

### 1. `FLOPS` vs `TFLOPS` vs 实际吞吐

- `FLOPS`：每秒浮点运算次数
- `TFLOPS`：`10^12 FLOPS`
- 理论 `TFLOPS` 不等于真实 kernel 吞吐

### 2. `内存带宽` vs `显存容量`

- 带宽决定搬得快不快
- 容量决定放不放得下

### 3. `ZeRO` vs `FSDP`

- `ZeRO` 是思想 / 分 stage 的内存分片路线
- `FSDP` 更像 PyTorch 生态里对这类思想的工程实现之一

### 4. `PagedAttention` vs `FlashAttention`

- `PagedAttention` 主要在解 KV cache 管理和显存碎片
- `FlashAttention` 主要在解 attention kernel 的 IO 问题

### 5. `Continuous Batching` vs `Prefix Caching`

- 一个是调度策略
- 一个是跨请求复用策略

### 6. `PD 解耦` vs `PD 分离`

- 一个偏软件调度语义
- 一个偏物理资源拆分
