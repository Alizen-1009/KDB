# 两张 GPU 部署模型时如何选择 TP 与 PP？

- 整理状态：已整理
- 题目出处：用户提供的 2026-10-10 面试回忆；答案根据本次对话整理

## 问题背景

两张 GPU，比较推理部署的 TP=2 与 PP=2；未指定模型、卡型、互联和请求规模。

## 30 秒回答

TP 在每层内部切权重，两卡协同完成同一层，适合高速互联、层内矩阵较大和单请求时延优先的场景。PP 沿层深切两段，主要在 stage 边界传激活，适合较慢互联、可按层均衡切分且有足够独立请求或 microbatch 填满流水线的场景。先检查权重、KV Cache 和运行时显存，再比较实际时延和吞吐；模型及目标 KV 能放入单卡时，也比较两个独立副本。

## 深入解释

| 比较项 | TP=2 | PP=2 |
|---|---|---|
| 切分对象 | 每层内部的矩阵 | 前后不同层 |
| 通信 | 层内/子层边界反复集合通信 | 主要在 stage 边界点对点传激活 |
| 互联要求 | 对带宽和同步延迟更敏感 | 相对适合较慢链路 |
| 并行来源 | 同一层的工作拆给两卡 | 不同工作单元在不同 stage 交错 |
| 显存条件 | 层内张量能按框架支持的布局切分 | 每个 stage 及其中的单层能放入对应卡 |
| 风险 | 通信抵消计算节省，切小后 GEMM 效率下降 | bubble、stage 不均衡和调度限制 |

TP 需要模型和 kernel 支持相应分片；常见 TP 层存在维度可整除或特定复制规则，不能只凭总显存相加就认定能部署。PP 要按实际耗时和显存分配 stage，不是机械均分层数；框架必须支持对应模型和流水调度。

### 单请求自回归依赖

第 t+1 个 token 依赖第 t 个 token 完成整个模型后得到的采样结果。同一请求的相邻 decode token 不能直接作为两个独立任务填满 PP。需要其他请求或可独立推进的 microbatch 交错。

机制示例：忽略通信和调度，两段各耗时 t，一个工作单元的 PP 时延仍约 2t。多个独立工作单元流水执行，理想稳态才可能每 t 完成一个。PP 不会直接让单请求时延减半；TP 的时延改善也必须超过其通信成本。
