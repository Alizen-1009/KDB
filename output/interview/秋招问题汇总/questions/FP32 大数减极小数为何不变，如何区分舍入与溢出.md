# FP32 大数减极小数为何不变，如何区分舍入与溢出？

## 原题与条件

FP32 下 9.9*10^9 - 1.0*10^-9 等于多少？会溢出吗？结果是什么？

## 30 秒回答

不溢出，是有效精度不足。9.9×10⁹ 附近 FP32 的相邻数间隔为 1024，减去 10⁻⁹ 不能改变舍入结果。在通常 round-to-nearest 下，9.9e9 转 FP32 是 9900000256，减法后的 FP32 结果仍为该值。范围足够不代表能表示微小差值。

## 深入解释

FP32 正常数有 24 位二进制有效精度。因为：

$$2^{33}<9.9\times10^9<2^{34}$$

该区间 ULP 为：

$$2^{33-23}=1024$$

通常 round-to-nearest 下，9.9e9 被表示为 9,900,000,256；1e−9 远小于半个 ULP，所以减法舍入回同一数值。它远小于 FP32 最大有限值约 3.4×10³⁸，不是 overflow；本例也不是 subnormal underflow。

本轮对话已用 Python 标准库核对 binary32 转换和结果：

```python
import struct

def f32(x):
    return struct.unpack('f', struct.pack('f', x))[0]

x = f32(9.9e9)
y = f32(1e-9)
print(x, f32(x - y))
# 9900000256.0 9900000256.0
```

这验证的是数值转换与舍入示例，不是 CUDA kernel 实测。若在 C++ 中验证，要注意浮点字面量后缀、表达式提升和舍入模式。
