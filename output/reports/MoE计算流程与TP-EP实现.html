01

完整计算流程

每个 token 只选择少数 expert；省下的是 active FLOPs，增加的是动态路由、重排和通信。

RouterX @ Wrouter
得到 [T,E] logits
Top-k每个 token 选择 K 个 expert 与权重
Populate按 expert 建立连续物理 row 映射
C1 GEMMGate + Up 两个 expert projection
EpilogueSwiGLU；可融合 NVFP4 量化
C2 GEMMDown projection 回到 hidden size
Finalize逆置换并按 routing weight 合并

核心数学

logits       = X @ W_router                 # [T,E]
topk_ids, p  = TopK + normalize(logits)      # [T,K]

route_id = token_id × K + kth            # R = T × K routes

gate_e = X_e @ W_gate_e
up_e   = X_e @ W_up_e
mid_e  = SiLU(gate_e) ⊙ up_e
out_e  = mid_e @ W_down_e

Y[token] = Σ_k p[token,k] × out(route(token,k))
02

先记住三个词

一个管动态 token，一个管静态权重，一个管 GEMM 之后的后处理。

DYNAMIC METADATA

Populate

把 token 的 Top-k 路由结果整理成 expert GEMM 可消费的连续 row mapping。

permuted_row → route_id → token_id
STATIC WEIGHTS

Preshuffle

模型加载时把 expert 权重预先变成 TMA / Tensor Core 需要的物理布局。

[E,N,K] → tiled / packed / swizzled bytes
POST MMA

Epilogue

读取 accumulator，执行 activation、scale、quantize、cast、store 或 combine。

TMEM → SwiGLU → NVFP4 → C2 input

不一定真的复制 activation

MATERIALIZED

显式 Dispatch

根据 mapping 把 X 复制成 expert-contiguous buffer。GEMM 读取规整，但多一次中间读写。

FUSED GATHER

Loader 直接 Gather

只保存 mapping，GEMM loader 用 token = route / top_k 从原始 X 读取。省去 permute kernel，但 mainloop 有间接寻址。

V1 INSIGHT

Atomic 旧值就是 Slot

atomicAdd 返回的旧 count 正好是 expert 内 slot，可保存下来避免 Populate 再做一次竞争 atomic。

04

Preshuffle：把权重预先翻译成硬件方言

这是静态权重的物理布局转换，不是运行时 token permutation。

逻辑权重 W_gate_up [E, 2H, D]
W_down [E, D, H]
→
Kernel 物理布局 tile / transpose / BlockMajorK
FP4 nibble packing / scale interleave
TMA alignment / SMEM swizzle
!
Preshuffle 是 ABI，而不是“同一个 Tensor 的另一种 view”

TensorRT、CuTe DSL 与自研 kernel 如果期待不同的 physical layout，就不能直接共享同一份 bytes。要么统一布局，要么保存两份权重或增加转换。PD 不分离时，多个执行路径共用同一模型权重，这个兼容约束尤其重要。

05

Epilogue：MMA 结束，不代表 GEMM 结束

Mainloop 负责累加，Epilogue 把 accumulator 变成下一个算子真正能消费的输出。

C1 Gate-Up Epilogue

TMEM Accumulatorsgate 与 up 的 FP32 accumulation
→
SwiGLUSiLU(gate) × up
→
NVFP4 Output16-element absmax / scale / convert / pack，直接成为 C2 输入

C2 Down Epilogue 与 Finalize

Down Accumulator每条 route 的 expert output
→
Scale / Cast / Weight可乘 routing weight，或先写 permuted output
→
Finalizeinverse-permute；同一 token 的 K 条 routes 加权求和
≠
TMEM 让重 Epilogue 更容易解耦，但不是免费

量化、packing 或 store 太慢仍会产生 backpressure。真正重叠需要 TMEM 双缓冲、正确 fence/barrier，以及足够的 RF、SMEM 和 store 吞吐。

06

沿两种并行方式追踪数据

切换标签，观察“token 去哪里”和“权重怎么切”——这正是 TP 与 EP 的根本区别。

TP：每张卡参与每个 expert，但只算矩阵的一部分

所有 TP ranks 通常看到相同 token 和相同 Router 结果；expert 的 intermediate 维 H 被切成 H/P。

TP Rank 0 H/P shard
  • 全部 experts 的 shard
  • 相同 X / Top-k / Populate
  • C1 local intermediate
  • C2 partial [T,D]
TP Rank 1 H/P shard
  • 全部 experts 的 shard
  • 相同 X / Top-k / Populate
  • C1 local intermediate
  • C2 partial [T,D]
TP Rank P−1 H/P shard
  • 全部 experts 的 shard
  • 相同 X / Top-k / Populate
  • C1 local intermediate
  • C2 partial [T,D]
C2 partial outputs → TP All-Reduce / Reduce-Scatter → 完整 Y
Router 与 Populate 在各 rank 重复没有 token 为寻找 expert 而做 All-to-All。
C1 产生 local H/P shard每 rank 只执行本地 Gate-Up 与 NVFP4 Epilogue。
C2 产生 D 维 partial sumWdown 沿输入 H 切分，因此各 rank 结果必须求和。

EP：expert 固定在 owner rank，token 跨卡去找它

每个 rank 保存部分完整 experts；Router 使用全局 expert id，activation 经两次动态多对多交换。

EP Rank 0 experts 0…m
  • 本地 token source
  • 接收目标为本地 experts 的 routes
  • 完整 C1 / C2
EP Rank 1 experts m+1…
  • 本地 token source
  • 接收目标为本地 experts 的 routes
  • 完整 C1 / C2
EP Rank Q−1 last experts
  • 本地 token source
  • 接收目标为本地 experts 的 routes
  • 完整 C1 / C2
Dispatch All-to-All：activation + route metadata → expert owner ranks
Combine All-to-All：expert outputs → original token ranks
Source Populate按目标 rank / expert 构建 send layout。
Destination Populate把接收 routes 整理成本地 expert-contiguous rows 并 padding。
Owner rank 执行完整 Expert FFN没有 expert 内 TP 时，本地 C2 不需要 partial all-reduce。
Source rank Finalize输出返回原 token rank，再按 Top-k routing weights 合并。

EP + TP：先找 expert，再由一组 GPU 共同计算它

Expert 集合先沿 EP 分布；每个 expert 的 Gate-Up/Down 矩阵再沿 TP 切分。

EP size 与 TP size 不必相等

二者切的是不同维度。具体 collective 顺序、并行组重叠方式和是否能融合，由框架与部署拓扑决定。

07

TP 与 EP 对照表

一句话：TP 是“多卡一起算同一个矩阵”，EP 是“token 跨卡去找自己的 expert”。

观察维度TP-only MoEEP-only MoE
Expert 权重每 rank 保存全部 experts 的 tensor shard每 rank 保存部分完整 experts
Token 是否跨卡通常不跨卡找 expert通过 Dispatch All-to-All 找 owner
Router / Populate各 TP rank 通常重复执行Source 与 destination 都可能构建 mapping

主要通信C2 后 All-Reduce / Reduce-ScatterDispatch + Combine All-to-All

主要风险层间同步、高频 collective、控制开销复制负载不均、消息碎片、跨节点带宽与 tail

Prefill 特征更大的 local GEMM 与 collective payload更容易形成大 expert batch，但 All-to-All 字节更多
08

最后，用三句话记住

看到 Fused MoE 源码时，先判断变量属于 token 路由、权重布局，还是 accumulator 后处理。

POPULATE

动态 token 坐标

这一轮 token 去了哪些 experts？Grouped GEMM 的每个物理 row 对应哪条 route？

PRESHUFFLE

静态权重字节

相同数学权重如何摆放，才能被当前 TMA、Tensor Core 和 scale layout 直接消费？

EPILOGUE

Accumulator 的下一站

MMA 之后是否融合 SwiGLU、NVFP4、scale、cast、store 或 token combine？
