从模型公式到 serving 状态

TTT：把隐藏状态变成一个会在线学习的小模型

本指南围绕一个问题组织：历史不再作为 token 列表保存，而被写进 learner 的权重后，模型、并行算法与推理系统分别付出什么代价？

一句话答案：TTT Layer 是一种 RNN-like 层——每个 token 先通过局部自监督损失更新内部 learner 权重 W_t（写状态），再用查询视图从更新后的 learner 读取输出（读状态）；外循环则训练这套“如何写、如何读”的规则，使其服务于语言模型 next-token prediction。

5 分钟学习路线

  1. 1 分钟：看四类“历史状态”对比。
  2. 2 分钟：沿单 token 流程读三个公式。
  3. 1 分钟：分清内外循环与 strict equivalence。
  4. 1 分钟：看 benchmark 边界和 serving 清单。

证据标签

【论文/来源事实】 【实验观察】 【工程推导】 【待核实】

标签同时用文字与颜色编码；工程推导不冒充论文已实现，版本相关能力不冒充当前 runtime 事实。

01 · Mental model

先问：历史到底存在哪里？

【论文/来源事实】 TTT 的新意不只是“测试时算梯度”，而是把序列层的隐藏状态从向量或聚合矩阵，升级为一个可学习函数的参数。以下统一以“每请求、每层”为观察单位，维度符号只用于建立数量级直觉。

统一维度账本：T 为已处理 token 数，d 为状态/模型宽度，d_k,d_v 为 key/value 维度。
序列机制历史载体典型形状随 T 增长？读写方式回退/复用直觉
Transformer显式 KV CacheK:[T,d_k]
V:[T,d_v]		是，线性增长追加当前 K/V；Q 读取历史行token/page 边界清晰，较自然做 prefix 复用
普通 RNN隐藏向量h_t:[d]否递推覆盖向量需保存边界状态；无法恢复任意历史 token
线性注意力fast-weight 矩阵状态S_t:[d_k,d_v]否外积/结构化递推写入；Q 乘矩阵读取需 checkpoint 聚合状态；不能自然逐 token 删除
TTT-Linearlearner 权重W_t:[d,d]否对自监督损失做梯度更新；用 Q-view 查询需 checkpoint learner；更新、复制、回滚更复杂
TTT-MLP多层 learner 权重多组矩阵；隐藏层通常扩到输入的 4×否更新 MLP 参数；执行 MLP 查询状态更强也更重；I/O 与 checkpoint 压力更大

固定大小 ≠ 状态小。 【论文/来源事实】

不随 T 增长只说明渐近形态稳定。每请求、每层一个 d×d 方阵，或一个带多组参数的 MLP learner，仍可能比普通 RNN 的 d 维向量大很多；TP 分片、dtype、层数与并发请求数都会进入显存账本。

可以把四类机制压缩成一句对比：Transformer 保存“原始索引卡片”，普通 RNN 保存“摘要向量”，线性注意力保存“聚合关联表”，TTT 保存“读写历史后改变了参数的 learner”。

02 · Read after write

一个 token 如何先写状态、再读状态

【论文/来源事实】 当前 token x_t 被投影成 training / label / test 三个视图。training 与 label 视图定义“学什么”，test 视图定义“怎么问”。

1构造局部训练样本θ_K x_t 是输入，θ_V x_t 是重建目标。
2推进 learner 状态在 W_{t-1} 处求梯度，得到序列私有的 W_t。
3查询更新后 learnerθ_Q x_t 进入 f(·;W_t)，产生层输出 z_t。
03 · Core equations

三个公式：写什么、怎么写、怎么读

① 多视图重建损失：定义“写入信号”

l(W; xt) = || f(θKxt; W) − θVxt ||²

【论文/来源事实】 learner 用 training view 作为输入，尝试重建 label view。平方误差衡量“当前 learner 对该 token 的局部任务做得多差”。这不是 next-token prediction。

② 梯度更新：把当前 token 写进隐藏状态

Wt = Wt−1 − η ∇W l(Wt−1; xt)

W_{t-1} 是过去所有 token 作用后的 learner 权重；梯度方向来自当前 token 的重建误差；η 控制写入步长。论文实现中还涉及 token-dependent learning rate 等由外循环学习的设计。

③ 查询输出：从新状态读取

zt = f(θQxt; Wt)

查询使用的是刚更新出的 W_t。因此同一个 x_t 同时参与“写状态”和“读状态”，但三个投影视图的职责不同。

θK：training viewlearner 接收什么输入。
θV：label viewlearner 被要求重建什么。
θQ：test view当前输出如何查询已写入的状态。
04 · Hand calculation

教学用标量玩具例子，不是论文真实维度

目的只有一个：展示“先写状态、再读状态”。它不展示多维投影、mini-batch、LayerNorm、残差、token-dependent learning rate，也不能代表真实数值稳定性或性能。

设定

f(q; w)=wq
w0=0, k=2, v=1, q=3, η=0.1

这里把 θ_Kx_t 简写为 k，把 θ_Vx_t 简写为 v，把 θ_Qx_t 简写为 q。

逐步手算

  1. 损失：l(w)=(wk-v)²=(2w-1)²。
  2. 梯度：dl/dw=2(wk-v)k，在 w₀=0 处为 2(0×2-1)×2=-4。
  3. 写状态：w₁=w₀-η(-4)=0-0.1×(-4)=0.4。
  4. 读状态：z=f(q;w₁)=w₁q=0.4×3=1.2。

你应该带走的唯一机制：重建误差让 learner 权重从 0 变成 0.4，随后查询看到的是新权重，因此输出为 1.2。这就是最小化的 read-after-write。

05 · Meta-learning view

内循环 vs 外循环：两个目标、两种时间尺度

内循环：每条序列内部推进状态

【论文/来源事实】
  • 输入当前 token 的 K/V 视图。
  • 优化多视图重建损失。
  • 推进 W₀ → W₁ → … → W_T。
  • W_t 对外循环而言是 activation / hidden state。
  • 测试序列也会推动该序列私有 learner 状态。

外循环：训练“如何学习”

【论文/来源事实】
  • 目标是语言模型 next-token prediction。
  • 学习 θ_K / θ_V / θ_Q。
  • 学习初始化 θ_init = W₀。
  • 学习 token-dependent learning rate。
  • 共同训练 backbone 与网络其他参数。

两个必须纠正的说法：

① 内循环不是 next-token prediction；next-token prediction 属于外循环语言模型目标。② serving 时推进 TTT learner 状态不是拿标签微调整个 LLM；被更新的是 TTT 层内部、每序列私有的 hidden-state learner。

外循环可被理解为：寻找一种视图投影、初始 learner 和写入速度，使得“在序列内做局部自监督学习”最终有利于语言建模。这个视角接近 meta-learning，但本文不把 TTT 泛化为所有 test-time adaptation。

07 · Parallelization

Mini-batch TTT 与 dual form：把串行学习变成硬件可执行的块

为什么严格 online GD 难并行

【论文/来源事实】 online GD 的第 t 个梯度在 W_{t-1} 处计算，而 W_{t-1} 又依赖前一个 token，时间轴形成长串行链。batch GD 则让整个批次的梯度都在同一个批前状态计算，容易并行，但状态适应粒度最粗。

1234 5678 9101112 13141516
一个 mini-batch：b=16；16 个梯度共享批前状态，可批内矩阵化
批末统一推进 learner state；第 17 个 token 所在的下一批再从这个新状态开始。论文主要实验使用 b=16，但这不是通用最优值。

Online GD · b=1

最细粒度适应；每步依赖前态，时间并行度最低。

Mini-batch · b=16

论文主要实验折中：批内并行、批间推进。不是通用最优值。

Batch GD · b=T

整段共享初始状态计算梯度，最易矩阵化，偏离 online adaptation 最大。

Dual form 在解决什么

Primal：显式参数空间

若逐 token 物化梯度/更新，中间对象可呈现多个 d×d 矩阵。瓶颈不仅是算术，还包括这些矩阵的生成、读写与存储。

→

Dual：样本/小批空间重写

直接推导小批输出和批末状态，把外积与累计组织成加速器擅长的 matmul，避免物化全部 d×d 中间矩阵。

不要说“dual form 减少 FLOPs”。 【论文/来源事实】

更准确的系统口径是：dual form 保持数学输出不变，通过重写数据流、避免不利的中间矩阵物化，并可能用额外算术换取更高 matmul / 加速器利用率。因此单看 FLOPs 无法预测 wall-clock。

08 · Theorem boundaries

理论等价只在边界内成立

定理 1：TTT-Linear ↔ 最简无 softmax linear attention

【论文/来源事实】

等价需要以下条件同时成立：

f(x)=Wxbatch GDη=1/2W₀=0特定 θ_K/θ_V/θ_Q views
Wt = Σs≤t (θVxs)(θKxs)ᵀ
zt = Wt(θQxt)

这与最简 linear attention 的 fast-weight 累积一致。但实际 TTT-Linear 还包含 mini-batch、LayerNorm、残差、可学习初始化和学习率，因此实际 TTT-Linear 不等同于 linear attention。

定理 2：Nadaraya–Watson learner ↔ softmax self-attention

【论文/来源事实】

使用保存历史样本列表的 Nadaraya–Watson 非参数 learner 与指数核，可以得到与 softmax self-attention 相同的输出。这里的 learner 状态会随序列增长；它不是固定大小 W_t。

意义：提供“attention 也可看成 test-time learner”的统一解释。不意味着：自动得到新的高效 softmax-attention kernel，或消除 KV 历史增长。

判断等价的三问：learner 是否相同？更新规则与初始化是否相同？状态是否同样随上下文增长？任一答案不同，就不能只凭“都像 fast weights”宣称同一算法。

09 · Evidence ledger

来源 benchmark：实验支持什么，不支持什么

【论文/来源事实】 当前资料覆盖 Pile 2k / 8k 与 Books3 1k–32k 上下文。TTT / Transformer 规模为 125M / 350M / 760M / 1.3B；Mamba 对应 130M / 370M / 790M / 1.4B。

口径纠正：第一篇二手文章中的 250M 是误记；本报告只采用原论文口径 350M。

观察到了什么

【实验观察】
  • Pile 2k：来源整理称 TTT-Linear、Mamba、Transformer 大致接近；TTT-MLP 的额外 FLOPs 会抵消部分 perplexity 优势。
  • Pile 8k：来源报告 TTT-Linear / TTT-MLP 相对 Mamba 的优势扩大。
  • Books3 1k–32k：上下文拉长时，来源报告 TTT 相对 Mamba 的优势更明显，32k 是当前资料上界。
  • Transformer 原始 perplexity 仍可保持竞争力，但长上下文计算成本更高。
  • TTT-MLP 的内存 I/O 与实际 wall-clock 仍是主要限制。

不能推出什么

【待核实】
  • 不能推出在更大模型或百万上下文上仍保持同样趋势。
  • 不能从 perplexity 排名推出生产吞吐、P99、TTFT 或 TPOT。
  • 不能推出主流 serving runtime 已完整支持 learner state 生命周期。
  • 不能把特定 JAX/TPU 训练收益、GPU inference kernel 结果泛化到任意后端。
  • 不能隔离证明收益全部来自 TTT learner；Mamba-inspired backbone 也参与比较。

证据结论：现有实验支持“在所测约 1.3B、最长 32k、以 perplexity 为主的研究设置中，表达性固定状态值得继续研究”，但不支持“TTT 已是生产 Transformer/Mamba 替代品”。本文不添加任何未提供的 perplexity、吞吐或硬件数字。

10 · Serving implications

推理工程含义：learner state 不是普通 KV page

【工程推导】 本节是从状态语义推导出的系统问题清单，不代表论文或当前 repo 已完整实现。具体 API、checkpoint 格式、runtime 支持与 kernel 性能均需绑定版本核实。

每请求、每层 learner state调度器不仅管理 token KV 块，还要为每个活跃请求、每个 TTT 层持有 W_t；TTT-MLP 可能是多组参数状态。
Checkpoint 与迁移抢占、PD 交接或跨 worker 迁移时，需要冻结某个 token 边界的 learner state，并保证 dtype、layout、版本和层顺序一致。
Prefix 复用共享前缀不能只记录“命中多少 token”；需要有该边界对应的 learner checkpoint。状态已压缩历史，无法像 KV 行一样自然截取任意更短边界。
Speculative decoding 回滚被拒绝的 draft token 已推进 learner 时，runtime 必须恢复接受边界状态，或保留旧状态、做 copy-on-write / replay；直接原地覆盖会破坏语义。
Continuous batching每个请求处于不同序列位置与 learner 状态。batch slot 重排、请求完成、暂停与恢复都要与状态槽生命周期一致。
TP / Sharding若 W_t 被分片，每步更新和读取必须遵守与权重布局匹配的 collective / 本地 shard 语义；请求迁移还可能涉及重分片。
HBM 写流量KV decode 以读历史和追加小块为主；TTT 则反复更新较大 learner 权重。即使状态固定，写流量、读改写与中间量也可能成为瓶颈。
Kernel 支持需要把投影、损失、梯度、状态更新和查询映射成高利用率 kernel；dual form 只是数学/数据流基础，不等于任意 runtime 已有高性能实现。

一个实用的状态事务模型

begin(token boundary) → read Wt−1 → propose updates → commit Wt / rollback → expose zt

【工程推导】 把每次状态推进看成“有提交边界的事务”，能统一理解 prefix checkpoint、speculative rejection、请求迁移和 batch slot 生命周期。它是设计思路，不是论文声称的现成 runtime API。

11 · Corrections

常见误区

“TTT 就是 serving 时微调整个 LLM。”错。更新的是 TTT 层内部、每序列私有的 learner hidden state，不是用标签改全模型共享参数。
“内循环目标是 next-token prediction。”错。内循环是 θ_K/θ_V 多视图重建；next-token prediction 是外循环目标。
“TTT-Linear 就是线性注意力。”错。仅在 linear learner、batch GD、η=1/2、W₀=0 与特定视图同时成立时等价。
“固定大小状态一定省显存。”错。固定只是不随上下文增长；每请求、每层的方阵或 MLP 权重仍可能很大。
“Dual form 的核心是减少 FLOPs。”错。它主要重写数据流、避免物化不利的 d×d 中间矩阵，并可能用更多算术换硬件利用率。
“b=16 是理论最优 mini-batch。”错。它是论文主要实验中的折中，不是跨模型、硬件和上下文的通用最优。
“定理 2 给出了更快的 softmax attention kernel。”错。Nadaraya–Watson learner 的状态随历史增长；定理提供统一解释，不自动带来高效 kernel。
“研究 perplexity 优势等于生产 serving 优势。”错。现有证据最大约 1.3B、32k，主要看 perplexity；状态管理、延迟、吞吐和硬件适配需要独立验证。
12 · Self test

学习自测：8 题

先口头回答，再展开答案。<details> 可用键盘聚焦并切换。

1. 用两句话解释 TTT 是什么，以及一个 token 的读写顺序。

TTT Layer 把 RNN-like 隐藏状态定义为内部 learner 的权重。当前 token 先用 K/V 多视图重建损失把 W_{t-1} 更新为 W_t，再用 Q 视图查询 W_t 得到 z_t。

2. 为什么“固定大小状态”不等于“状态很小”？

固定只表示大小不随上下文长度 T 线性增长。TTT-Linear 每请求、每层可能保存 d×d 矩阵，TTT-MLP 还包含多组权重；层数、并发、dtype 与分片都会放大实际显存。

3. 内循环和外循环分别优化什么？

内循环对当前序列的多视图重建损失更新 learner 状态 W_t。外循环用语言模型 next-token prediction 训练 K/V/Q 视图、初始权重、token-dependent learning rate、backbone 和网络其他参数。

4. Mini-batch TTT 在什么两者之间折中？为什么 b=16 不是定律？

它在 online learning 的细粒度适应与批内并行度之间折中：小批更接近逐 token 更新，大批更易矩阵化但适应更粗。b=16 是论文主要实验设置，最优点会受模型、序列、硬件和实现影响。

5. Dual form 的正确性能表述是什么？

它把参数空间中的外积/累计重写到小批矩阵运算，避免物化大量 d×d 中间矩阵，并提升 matmul / 加速器利用率。它不应被简化成“减少 FLOPs”，因为可能用额外算术换更好的硬件执行。

6. TTT-Linear 在哪些条件下才等价最简 linear attention？

f(x)=Wx、batch GD、η=1/2、W₀=0，并使用特定 θ_K/θ_V/θ_Q 视图。实际 TTT-Linear 含 mini-batch、LayerNorm、残差、可学习初始化和学习率，因此不等同。

7. 当前实验能支持哪一级结论？不能支持哪一级？

可支持：在约 1.3B、最长 32k、以 perplexity 为主的研究设置中，TTT 相对 Mamba 的长上下文趋势值得关注。不可支持：百万上下文、更大模型、生产吞吐/延迟、主流 runtime 已成熟支持，或 TTT 已全面替代 Transformer/Mamba。

8. Speculative decoding 为什么会让 TTT 状态管理更难？

draft token 若已推进 learner state，而验证后部分 token 被拒绝，runtime 必须恢复到最后接受边界。需要旧状态、checkpoint、copy-on-write 或可重放更新；原地覆盖且无回滚会让后续状态错误。
