01 / MENTAL MODEL

先问六个问题，再看任何缩写

每项技术都应回答：改了模型哪一轴？历史信息存在哪里？每个 token 读什么？节省什么？牺牲什么？代表模型如何组合？

01机制分属不同轴MLA 改 KV 表示，DSA/QSA/MSA 改历史选择，GDN/KDA 改历史载体，mHC/AttnRes 改深度信息流，Engram/LatentMoE 改容量。它们通常不互斥。
02先进模型往往组合同一模型可以同时使用压缩 KV、稀疏检索、固定递归状态、残差拓扑和 MoE；“A 还是 B”经常问错了层级。
03三个账本必须分开FLOPs、KV/state 容量与实际墙钟受不同因素支配。索引、Gather、内存访问、通信和 kernel 规则性会让理论节省不等于部署收益。
wiki 归纳 一个实用总式：表示决定“存成什么”，选择决定“读哪些”，状态决定“是否还保存逐 token 历史”，残差决定“沿深度如何读”，容量模块决定“参数知识放在哪里”。

03 / SIX AXES

六轴知识地图

把每项机制放回正确坐标，可避免把“压缩表示”“稀疏选取”和“固定状态”混成同一种长上下文技术。

KV 表示

历史 token 存成什么？

MLA 的 latent cKV；MLA 的 MHA/MQA 是两种等价数据流形态。

历史选择

当前 query 实际读哪些历史？

MSA、DSA、QSA、NSA、CSA/HCA；粒度可为 token、block 或 compressed entry。

固定递归状态

是否仍保留逐 token KV？

GDN/KDA 把长期历史递推进固定矩阵，并另存 short-conv state。

Indexer 复用

检索结果能否少算几次？

IndexShare 复用 top-k indices；跨层和跨 MTP iteration 是两个维度。

层间残差

历史层表示如何进入当前层？

mHC 维持多路 stream 并稳定混合；AttnRes 对历史层做 depth-wise softmax。

静态 / 专家容量

参数知识在哪里被访问？

Engram/n-gram 走确定性查表；LatentMoE 让 routed experts 在低维潜空间工作。

05 / MLA MODES

MLA 双模式：同一低秩结构的两种执行形态

一手资料 MLA 先联合压缩 KV 为 cKV，并用 decoupled RoPE 把 content 与位置路径分开。MHA/MQA mode 的关键不是“换 checkpoint”，而是矩阵吸收前后的数据流。

cₜᴷⱽ = Wᴰᴷⱽ hₜ kᶜₜ,ᵢ = Wᵁᴷᵢ cₜᴷⱽ vᶜₜ,ᵢ = Wᵁⱽᵢ cₜᴷⱽ scoreᶜᵢ(t,s) = qᶜₜ,ᵢᵀ Wᵁᴷᵢ cₛᴷⱽ = (Wᵁᴷᵢᵀ qᶜₜ,ᵢ)ᵀ cₛᴷⱽ

MHA mode of MLA

逻辑上为每个 head 恢复或使用 content Kᵢ/Vᵢ，再与各 head query 做常规多头 core attention；位置项由独立的 RoPE key 提供。

  • 缓存本质：底层仍可来自低秩 latent 与小 RoPE key。
  • 适合：训练与 prefill 中的大矩阵并行。
  • 代价：恢复/消费 per-head content K/V 会形成更宽中间数据流。

MQA mode of MLA

把 head-specific Wᵁᴷᵢ 吸收到 query 侧，把 Wᵁⱽᵢ 与 output 侧重排/融合；core attention 直接让所有 query heads 共享同一个 latent KV entry。

  • 缓存本质：cKV + 小型 positional key。
  • 适合：decode 与 DSA kernel 的跨 query 复用。
  • 边界：不是把模型粗暴改成普通 MQA。
模式事实。 DeepSeek-V3.1-Terminus 训练/prefill 使用 MHA mode，decode 使用 MQA mode；DSA 因 kernel 要求同一 KV entry 在多个 query 间共享，建立在 MLA 的 MQA mode。该等价依赖 MLA 的低秩映射、decoupled RoPE 与可吸收变换，不能泛化成任意 MHA checkpoint 都可无条件变成 MQA。 一手资料
06 / SPARSE & COMPRESSED SOFTMAX

稀疏 / 压缩 softmax 家族

一致阅读模板：一句话 → 流程 → 历史保留 → 收益 → 代价 → 代表模型 → 边界。共同点是仍有 softmax；差异在“对谁打分、选什么、core 看原 token 还是 compressed entry”。

MSA

GQA 块选择
一手资料

一句话：在标准 GQA 上，用超轻 Index Branch 为每个 GQA group 独立选块，Main Branch 在块内做精确 softmax。

  1. 每个 GQA group 一个 index query；所有 groups 共享一个 index key。
  2. 先做 token score，再按块 max-pooling；每组 top-k blocks，强制包含当前 local block。
  3. 主分支 gather 选中块的可见原始 token K/V，执行标准缩放点积 softmax。
  4. 训练用 group-averaged 主分支分布做 KL teacher，并配合 detach、indexer warmup、forced local block。
历史保留

完整标准 GQA KV；稀疏发生在读取。

收益

core 预算固定为约 k·B tokens；block 规则化利于 GPU。

代价 / 边界

Indexer 仍有轻量二次项；不是 MLA。代表 MiniMax M3 的 GQA+MSA。

DSA

latent token top-k
一手资料

一句话：lightning indexer 对每个历史 token / MLA latent entry 做细粒度排序，只让 top-k 进入 MLA MQA core。

  1. query 侧生成少量 index heads 与权重，历史生成共享 index key；ReLU 分数用于吞吐。
  2. DeepSeek V3.2 每 query 选择 k=2048 latent entries。
  3. Core 从 O(L²) 变为 O(Lk)，但 indexer 仍为 O(L²)。
历史保留

MLA latent KV cache，token 粒度。

收益

减少 core attention 对长历史的计算和读取。

代价 / 边界

选漏风险与高额迁移训练。约 2.1B warmup + 943.7B sparse CPT 是该论文模型事实，不可泛化。

QSA

pool 后选块
一手资料

一句话：只把 Indexer K 序列按 r=4 压短，再按块选择；Core 仍读取展开后的原始 token K/V。

  1. Indexer K 按不重叠 4-token micro-block average-pool；池化后赋 block position，再做 partial RoPE。
  2. Query 不压缩，使用当前 token position。
  3. 最多选 512 个完整块，展开为 K=2048 原始 token budget，并总是加入未完成 tail。
历史保留

Core Attention 的 token-level K/V 不压缩。

收益

Indexer 论文口径降为 O(L²/r)；core 只看预算内 token。

代价 / 边界

压缩仅发生在 Indexer K；不要写成 Core KV compression。代表 Qwen3.8-Flash-Next。

NSA

原生三分支
一手资料

一句话：原生可训练的三分支 sparse attention，把全局粗读、重要块精读与局部窗口分开学习。

  1. compressed：learned compressor 产生 coarse-grained K/V。
  2. selected：选择 fine-grained contiguous blocks，保留原 token 细节。
  3. sliding：固定局部窗口；三分支各有独立 K/V，输出由 learned gates 融合。
  4. GQA/MQA 场景下采用 group-consistent selection 与 group-centric kernel，组内 query heads 共享选块。
历史保留

三类重映射历史，不是单个 DSA indexer。

收益

层次化地覆盖全局、精细和局部模式，并面向 Tensor Core 规则块。

代价 / 边界

独立分支与门控更复杂；NSA 不是 DeepSeek V3.2 的 DSA。

CSA

低压缩 + top-k
HF 官方文档

一句话：DeepSeek V4 的 Compressed Sparse Attention：对共享 K=V 的历史做低压缩率 overlapping compression，再由 lightning indexer 选 top-k compressed blocks。

  1. 官方 Transformers 默认压缩率 m=4，窗口重叠。
  2. Indexer 对 compressed pool 排序并 gather top-index_topk entries。
  3. Core 同时读取选中的 long-range compressed entries 与共享 local sliding-window K=V branch。
历史保留

低压缩 overlapping entries + local exact K=V。

收益

压缩后再稀疏，保留较细远程分辨率。

代价 / 边界

需要 compressor overlap state、indexer 与 gather；与 HCA 不同。

HCA

重压缩 dense
HF 官方文档

一句话：DeepSeek V4 的 Heavily Compressed Attention：对共享 K=V 以高压缩率做 non-overlapping compression，不设 indexer，读取所有可见 compressed entries。

  1. 官方 Transformers 默认压缩率 m′=128，窗口不重叠。
  2. 远程 compressed entries 做 dense attention；另与 local sliding branch 拼接。
  3. 无 top-k indexer，cache 只需 compressor + local branch 状态。
历史保留

重压缩 entries + local exact K=V。

收益

去掉 indexer，远程序列长度大幅压短。

代价 / 边界

压缩分辨率更粗；仍对全部 compressed entries dense 读取。CSA ≠ HCA。

IndexShare

复用 indices
wiki 归纳

一句话：复用已经选出的 top-k token indices，避免重复运行 DSA indexer；它不是 attention。

  1. 跨 Transformer 层：Full Indexer 层计算一次，后续 Shared 层复用 indices，但各自使用本层 Q/K/V。
  2. 跨 MTP iterations：第一轮预测计算，后续迭代复用；与跨层共享正交。
共享什么

只共享 top-k indices。

不共享什么

不共享 QKV、KV cache、attention output。

代价 / 边界

逐层选择灵活性下降；代表 GLM-5.2，GLM-5.3-Flash 无跨层共享。

复杂度口径。 “Sparse”通常只把 core attention 变为 O(Lk) 或块等价形式；若 indexer 仍扫描全历史，它仍可能带有 O(L²) 或 O(L²/r) 项。总墙钟还取决于 top-k、Gather、block 规则性、batch/context、dtype、硬件与 backend。

训练/prefill 与 decode 是两种调度

Chunked training / prefill

时间轴切块，块内把因果递推改写为矩阵乘/triangular 变换或 scan，块间只传播最终 state。这里的 chunk 是算子内部计算粒度，不等于 serving 的 chunked prefill 调度。

Recurrent decode

每次一个 token：更新 Conv State 与 Matrix State，再原地推进。单步不需重读完整历史 KV，但状态读写与融合 kernel 仍决定墙钟。

Fixed state 不等于免费。 每请求、每层、每 head 的 dₖ×dᵥ 矩阵可能很大；prefix caching、请求迁移、投机回滚都需要 checkpoint、copy-on-write 或 replay。它也弱于显式 KV 的精确任意 token 检索，因此 Kimi K3、GLM-5.3-Flash 都与显式 attention 层混合使用。 wiki 归纳

09 / CAPACITY

容量家族：静态查表与潜在专家

这组技术不主要改长历史读取，而是在控制每 token 计算/通信的前提下，把更多参数容量放进模型。

Engram

Conditional Memory
一手资料

流程：local n-gram → tokenizer compression → multihead hash → table lookup → context gate → short conv → residual。

每 token 只算固定数量的哈希地址并读取固定 rows，因此 lookup 是 O(1) 数组索引，不随表大小扫描。表项是可训练模型参数；它不是 ANN，不是外部文档检索，也不是 RAG。代价在大表存储、碰撞、分片、预取和热点。

Qwen n-gram

加速器外静态表
论文事实

Qwen3.8-Flash-Next 最终只在 Layer 2 放一层 n-gram embedding；额外 51B 参数在 125B 主干之外并存于加速器外，host prefetch 与 Layer 1 计算重叠。

实现未披露 论文没有给出具体 n 阶、hash/slot、压缩方式或 hidden-state gate，不能把 Engram demo 的实现细节套过来。所谓“额外 latency 可忽略”也缺少带宽、命中率和端到端消融。

LatentMoE

低维 routed path
机制归纳
主干 x: [T,d] → down projection d→ℓ → router / experts: ℓ→m→ℓ → up projection ℓ→d → 主干 y: [T,d]

三维必须分清：d 是主干 hidden/residual width；ℓ 只存在于 routed expert 路径；m 是 expert FFN intermediate width，通常不等于 ℓ。

expert 权重主导尺寸与 EP activation payload 可从 d 相关降到 ℓ 相关，但新增上下投影、可能的信息瓶颈、token permutation、collective latency 与小 GEMM 仍要记账。Kimi K3 的 Stable LatentMoE 是代表实例。

11 / DESIGN TREE

设计选择树：先定位瓶颈，再选机制

  • 瓶颈是 decode 读取显式 KV 的字节数？
    • 希望保留多头表达且可接受专用 kernel：考虑 MLA 的 latent cache / absorbed MQA mode。
    • 愿意把多数历史压进固定状态：考虑 GDN/KDA，但保留周期性显式 attention 以补精确检索。
  • 瓶颈是长序列 core attention FLOPs？
    • 标准 GQA、重视 GPU 规则块：MSA。
    • 已有 MLA checkpoint、接受 token-level indexer 与 CPT：DSA。
    • 希望先压短 indexer 且 core 仍读原 token：QSA。
    • 希望原生三层次历史建模：NSA。
    • 希望 compressed-entry 路线：CSA（低压缩+索引）或 HCA（重压缩+无索引）。
  • 瓶颈是 indexer 自身？
    • 压短候选：QSA 的 pooled Indexer K。
    • 少算几次：IndexShare，但先验证跨层选择复用的质量边界。
  • 问题发生在深度信息流而非 token 历史？
    • 想保留多路 residual streams 并稳定 mixing：mHC。
    • 想对历史层表示做选择：AttnRes；工程上先看 Block 版本。
  • 瓶颈是参数容量与访问成本？
    • 局部稳定模式可确定性寻址：Engram / n-gram embedding。
    • MoE 的专家权重带宽与 EP payload 过宽：LatentMoE，并测量投影是否成为新瓶颈。
最终验收不是复杂度公式。 至少分别报告：模型质量、训练条件、prefill/decode、上下文与 batch、KV/state 容量、kernel/module latency、端到端 serving、硬件与并行拓扑。
12 / TEN MYTHS

10 条常见误区

“QSA 压缩了 Core KV。”

错。QSA 只压缩 Indexer K 序列；选块展开后，Core Attention 读取原始 token-level K/V。

“IndexShare 是一种 Attention。”

错。它只复用 top-k indices；每层仍用自己的 Q/K/V 和 attention 输出。

“Sparse Attention 自动让总复杂度线性。”

错。Core 可为 O(Lk)，但 DSA/MSA indexer 仍可能含 O(L²) 轻量项，QSA 为 O(L²/r)。

“Fixed state 可像 KV cache 一样任意回退。”

错。递归状态丢失逐 token 可逆性；回滚、迁移与 prefix reuse 需要 checkpoint/replay。

“Engram 就是内置 RAG。”

错。它是模型参数表的确定性哈希索引，不搜索外部文档，也不做 ANN。

“AttnRes 是另一种 token attention。”

错。它沿 depth 对历史层表示做 softmax，不选择上下文 token KV。

“LatentMoE 的 ℓ 是新的 hidden size，m=ℓ。”

错。主干保持 d；ℓ 是 routed path width；m 是 expert intermediate width，三者独立。

“CSA 与 HCA 是同义词。”

错。官方 HF 定义：CSA 默认 m=4 overlapping + indexer top-k；HCA 默认 m′=128 non-overlapping、无 indexer、dense 读 compressed entries。

“MLA 的 MHA/MQA 是两个不同 checkpoint 的简单二选一。”

错。它们是可吸收结构下的两种执行形态；等价依赖具体矩阵与 RoPE 分解。

“论文加速数字可以直接写进生产 SLO。”

错。必须保留硬件、dtype、batch、context、chunk、baseline 与 kernel/module/端到端边界。
