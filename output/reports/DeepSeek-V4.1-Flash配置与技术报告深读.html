01 · 一张配置里，其实有五种不同的“稀疏”

40 + 3 层40 层语言主干；3 层额外 DSpark 草稿网络。
4 组全局 KV第 2、8、14、20 层拥有独立全局缓存。
890 B/token包含量化 scale 的全局缓存有效载荷，非模型总显存。

论文面对的瓶颈是长任务 Agent：大量工具返回和历史记录增加 Prefill 计算，长上下文缓存占用 HBM，持久前缀缓存占用主机内存与 SSD，恢复请求又要搬运这些数据。优化目标覆盖计算、容量和 I/O。

维度配置 / 机制真正省的是什么
专家维384 个 routed experts，选 6 个；另有 1 个 shared expert每个 token 只激活部分 FFN 权重计算。
历史读取维index_topk=512核心 attention 每次只读被选中的历史条目，不是只存 512 条。
层维kv_source_layer_ids / index_source_layer_ids减少独立 KV 份数和重复索引计算。
序列表示维encoder ratio=2；decoder ratio=1encoder 两个连续 token 合成一个条目；decoder 保留逐 token 全局条目。
参数记忆维Engram N-gram 查表稀疏访问大规模学习到的记忆参数。

mHC 管理跨子层的残差流；CED 改变 decoder 全局 KV 的来源；FP4 改变表示精度；SWA Bounded Replay 改变缓存恢复策略。它们作用于不同环节，不能用一个“压缩率”概括。

03 · 一个 token 在 Attention 内部经历什么

5120 维 hidden 并不等于 64 × 512

hidden_size=5120 是子层输入输出宽度；num_attention_heads=64 和 head_dim=512 定义主 Q 的内部宽度 32768。不能用 5120÷64 推出这里的 head_dim。

主 Q：5120 → 1280（q_lora_rank）→ 64 × 512
局部共享 KV：5120 → 512
输出：64 × 512 → 8 组 × 4096 → 8 组 × 1024 → 5120

每组包含 8 个 Q heads；先组内把 4096 维投影到 1024，再合并 8 组并映射回 5120。这里的 q_lora_rank、o_lora_rank 是架构内置的低秩投影尺寸，不是后加的 LoRA 微调 adapter。

K=V：一个 512 维向量兼任两个角色

num_key_value_heads=1 告诉你各 Q heads 共享 KV；报告和实现进一步确认，主路径使用同一个 latent 作为 K 和 V。普通 MQA 仍可能分别保存 K、V，仅看这个字段不能推出 K=V。

全局条目和局部条目共同参与一次 attention 的候选集合，每层可见最多约 512 个全局条目与 128 个局部条目；这是两条分支的条目预算，不能保证对应 640 个互不重复的原始 token，短序列和因果边界也会减少有效条目。

ratio=2 是带学习权重的压缩，不是直接平均

uᵢ = Wkv hᵢ，zᵢ = Wgate hᵢ
c[j,d] = Σᵢ softmaxᵢ(z[i,d]) · u[i,d]，i 属于第 j 个二元组
cⱼ 再经 RMSNorm；完整组出现后才加入全局缓存。

各通道有自己的池化权重。CSA2 去掉旧 CSA 的重叠窗口和压缩器内绝对位置 embedding，Indexer K 直接从主 latent 投影得到，不再独立走一套压缩。ratio=1 直接投影和归一化，不做二元池化。

Indexer 是更便宜的检索器

index_n_heads=32 是检索 Q 的 head 数，index_head_dim=128 是每个检索 head 的宽度。每条 Indexer K 仍只有一个共享的 128 维向量，不能乘 32 计算缓存。

score(t,j) = Σₕ w[t,h] · ReLU( q_index[t,h] · k_index[j] )
selected(t) = Top512ⱼ score(t,j)

这些是轻量检索分数，决定“读哪里”；真正的主 attention 用 64 个 512 维 Q heads 重新计算注意力权重。共享 Top-K 不等于共享 softmax 权重。

分层索引：先全局找候选，再在候选里重排

第 20 层扫描全部可见全局条目，得到自己的 Top-512；另按块最大分数筛选 2048 个块。
共享候选池每块 8 个位置，共最多 16,384 个位置；每个 query 有自己的池。
24 / 28 / 32 / 36 层只在该池内重新选 Top-512，其余层直接复用。

第一遍全局扫描仍随 T 增长。固定候选池让后续索引每 query 的打分预算不随 T 增长，但不是整个模型严格 O(1)。在 1,048,576 长度下，候选池占 1/64；这也不是整体 64 倍提速。浅层漏掉的块无法被后续 Reindex 找回，是明确的质量权衡。

RoPE 的 64 维在 512 维内部

qk_rope_head_dim=64 表示 512 维中有 64 维旋转，余下 448 维不旋转，不是额外追加 64 维。共享 KV 同时作为 V，因此实现还对 attention 输出的对应通道做逆旋转，再进行输出投影。

original_max_position_embeddings=65536、factor=16 与最大 1,048,576 长度对应。YaRN 调整位置频率；它不是缓存压缩因子，也不能单凭 config 证明长上下文能力。参考实现对含全局分支的层使用 compress_rope_theta=160000 与 YaRN，纯 SWA 使用 rope_theta=10000；不能简化为所有局部支路永远用 10000。

论文 §2.2–2.3、§4.2.1；官方参考实现 Attention、Compressor、Indexer，具体版本见文末。

04 · CED 的重点是依赖关系，不是“少了 20 层”

这里的 encoder 仍是 causal 的：只看当前位置及之前的 token，不是双向编码器。前半网络处理完整输入，后半网络的全局 KV 由前半网络末端 hidden 生成。

论文记号：H₂₀ = encoder 的最终 hidden
decoder 全局 KV = Projection(H₂₀)
config 层号：encoder 为 0–19，decoder 从 20 开始。

在 CED 的一般描述中可有不同 decoder 层的 KV 投影；本配置进一步用 CSA2 让全部 decoder 层只保留第 20 层这一组。局部 SWA KV 仍来自各 decoder 层自己的 hidden，不能从 H₂₀ 一次投影出所有局部状态。

第一次输入一段很长的 prompt

  1. 输入 token / 图像 embedding 通过 0–19 层，生成三组 encoder 全局缓存及 encoder 输出。
  2. 从 encoder 末端表示建立第 20 层所有 prompt 位置的全局 KV；不需要所有 prompt token 跑完整个 decoder。
  3. 取 prompt 末尾 128 tokens 的 encoder 表示，运行后 20 层，重建 decoder 局部状态并取得末端预测。
  4. 开始生成后，每个新 token 正常经过完整 40 层，追加全局缓存并更新各层局部窗口。
对 N ≫ W 的输入，主干 token-layer 工作量示意：
普通路径：40N
CED + bounded replay：20N + 20W，W=128
比例 ≈ 1/2 + W/(2N)

这是展示依赖缩短的粗略账本，不包含不同层的真实 FLOPs、全局 KV 投影、视觉处理、通信和调度。8B/16B 激活参数来自论文，不是延迟承诺；短输入的收益不一定接近一半。

为什么 128-token SWA 恢复不是精确的

某一层最后 128 个位置的 KV，依赖下层这些位置的 hidden；下层 hidden 又需要更早的局部上下文。依赖沿深度向前扩张，所以精确恢复的历史范围随层数增长。论文用约 L×W 描述其开销。

Bounded Replay 只保留最近 W 个 token 的局部依赖；这些位置仍可读取已经缓存的全局历史。被截断的是更早的 SWA 路径，不是把整个模型的历史都缩成 128 tokens。

恢复对象何时使用处理方式
Encoder SWA历史全局 KV 命中，但 encoder 局部状态丢失重放缓存前缀末尾 128 tokens，再处理新后缀。重放只重建 SWA，不覆盖已存的全局 KV；新后缀生成新 KV。
Decoder SWA每次 CED Prefillprompt 最后 128 tokens 的 encoder 输出经过 decoder；所建局部状态用于 decode，不用于前缀持久缓存。

因此，同一段文字在不同 cache-hit 边界恢复，后续状态不保证逐 bit 或数学等价。论文称测得质量影响很小，并对 decoder replay 做后训练适应；这不是所有任务无损的证明。

论文 §2.2、§3.2.2。

05 · 把 890 bytes/token 一项项算出来

计算的是量化打包后的全局 KV 有效载荷：主 KV + Indexer K + 各自 scale。不是整个引擎实际分配量。此模型不使用 GDN，也没有需要套用 GDN 公式的递归矩阵。

一条全局记录数据Scale合计
主 KV，512 维512 × 4/8 = 256 B每 16 个通道一个 E4M3，512/16 = 32 B288 B
Indexer K，128 维128 × 4/8 = 64 B每 32 个通道一个 E8M0，128/32 = 4 B68 B
合计320 B36 B356 B

主 KV 使用接近 NVFP4 的 E2M1 + E4M3 分组 scale，但省去第二级全局 scale；Indexer 使用 MXFP4。顶层 quantization_config.weight_block_size=[32,32] 是权重配置，不能拿来覆盖主 KV 每 16 通道的 scale 分组。

Encoder：3 组 × floor(T/2) 条
Decoder：1 组 × T 条
M_global(B,T) = B × [3 floor(T/2) + T] × 356 bytes
偶数 T：M_global = B × T × (3/2 + 1) × 356
　　　　= B × T × 890 bytes

奇数 T 时尚未完成的二元组另存在 compressor 的固定小状态中。Top-K 和候选池是当前 query 的执行数据，不是为历史每个 token 永久附加的缓存。512 的 Top-K 不会把持久全局缓存限制成 512 条。

再加上固定的运行时局部状态

按论文 SWA FP8 口径，只计数据载荷，40 层 × 128 个窗口位置 × 512 维 × 1 byte = 2.5 MiB/序列。这是解码稳态的主干窗口数据，不包括量化 scale、页对齐和临时状态。若启用 3 个相同窗口和维度的 DSpark 层，局部数据再加 192 KiB。

官方参考 Compressor 的 3 个 ratio=2 source，各有 kv_state 与 score_state 两个 FP32 数组，每个 [B,2,512]；按这个实现，固定部分为 3×2×2×512×4 = 24 KiB/序列。它是未完成压缩组的暂存，不是 GDN 式长期递归矩阵。

HBM 的 1/4 与持久缓存的 1/8

论文的全局 KV 约缩至 V4-Flash 的 1/4。持久层额外不再保存 SWA，而旧部署的 SWA 约占持久容量一半，两者叠加得到相同 workload 下约 1/8。该数值依赖会话和缓存策略，不能看成任何输入的固定架构常数。

生产策略中，全局 KV 长期保留；encoder SWA 在短 TTL 的分布式主机内存池保存；缺失时 bounded replay；decoder SWA 不做前缀持久保存。运行时活跃请求仍需要 SWA 状态。

显存账本的边界：890 MiB 支持的是 1,048,576 tokens 的全局缓存，不表示模型能放入 1 GB 显卡。权重、Engram 放置、SWA、投机状态、通信 buffer、临时激活、分配器和多卡复制均需另算；TP 不能无条件把共享 MQA 缓存按 GPU 数平均除掉。

论文 §2.4.4、§3.2；量化分组由官方参考实现 kernel.py / model.py 交叉核对。缓存数字为上述布局的算术推导。

06 · 容量与跨层计算：MoE、Engram、Single-Pass mHC

MoE：552B 主干的主要参数在哪里

每个专家是 SwiGLU，主要有三个矩阵，参数约 3×5120×2304 = 35,389,440。40 层，每层 384 routed + 1 shared，专家矩阵合计约 544.997B，说明主干 552B 的绝大部分是专家权重。

每 token 经过 6 个 routed experts 加 1 个 shared expert。sqrtsoftplus 指路由分数先 softplus 再开方；校正 bias 只参与选专家，选中后的原始分数再归一化并乘 1.5。图像和文本有各自的负载平衡偏置。swiglu_limit=10 则限制激活幅度，改善低精度数值范围。

不要直接用 552B×6/384 推导 16B 激活量：attention、共享专家、其他模块都参与；Prefill/Decode 还受 CED 路径影响。仅 40 层七个专家的矩阵触达量约 9.909B，也不是整个模型的激活参数总量。

Engram：196B 表参数是怎样落到 config 的

engram_layer_ids=[1,14] 表示两个注入点。N-gram 阶数为 2、3、4，每阶 8 个哈希 heads，每 head 查 256 维，因此每次 lookup 有 3×8=24 个地址，拼接维度 24×256=6144。

表参数 = (384,006,168 + 384,016,682) × 256
　　　 ≈ 196.614B

两个 engram_num_embeddings 是每个模块多张哈希表拼在一起后的行数。engram_vocab_size=16000000 是哈希表规模配置，engram_compressed_vocab_size=99092 是规范化 token 编号空间，都不是语言模型输出词表 129280。

这是训练得到的参数记忆，不是用户对话的 KV，也不是外部检索。论文删除原 Engram 的短因果卷积；不能把早期 Engram 的卷积结构直接搬到 V4.1。确定性 N-gram 地址允许提前从主机内存预取，论文也指出 RL rollout 可把表留在 GPU 内存。196B 不应再被算进 552B 主干，也不能忽略其存储成本。

mHC：四路残差，不是四倍模型或四倍 KV

hc_mult=4 让残差状态形状成为 [B,T,4,5120]，子层实际读取时混合回 [B,T,5120]。可用下式理解：

Xₗ₊₁ = Bₗ Xₗ + Cₗ Fₗ(Aₗ₋₁ Xₗ)
(Aₗ,Bₗ,Cₗ) = H(Xₗ)

A 负责读出，B 混合已有残差，C 写回子层输出。hc_sinkhorn_iters=20 用于约束残差混合矩阵，和优化器里的 Sinkhorn balancing 是不同用途。

Single-Pass 让读系数来自前一个子块，避免等待当前 residual 的全维归约完成。这里的子块包括 attention 和 FFN：参考实现是上一 FFN 的 read mix 用于当前 attention，当前 attention 的 read mix 用于随后 FFN。生产 Mega-mHC 可融合残差更新、输入混合、系数预测、pre-norm 和转换，相关激活流量从 (4n+4)d 降到 (2n+2)d。减半指这段执行的激活访存，不是整个模型的显存或耗时。

论文 §2.4.1–2.5、§3.1.3；参数量为 config 的矩阵尺寸推导。

07 · 生成与视觉：config 剩余关键字段

DSpark 的“3 层”和“5 个位置”是两个轴

num_nextn_predict_layers=3 是草稿网络深度；dspark_block_size=5 是一次提出的草稿长度；不是三个 token，也不是保证一次接受五个 token。

dspark_target_layer_ids=[37,38,39] 选取主干靠后层的信息供草稿网络使用。当前参考实现取这些层之前的 residual 均值，拼为 3×5120，再投影回 5120；不是把这三个主干层删掉或替换成 drafter。

  1. 主干给出 anchor token 和中间特征；drafter 输入还包含 noise 占位位置。
  2. 3 层小网络一次算出 5 个位置的基础 logits。
  3. rank=256 的 Markov head 根据前一个已采样 token 顺序修正各位置 logits；大网络计算并行，轻量修正保留顺序依赖。
  4. confidence head 估计条件接受概率；生产 scheduler 结合硬件吞吐曲线和并发选择值得验证的前缀。
  5. target 验证后接受合法前缀，必要时回滚和修正；这些引擎动作不是 config 本身实现的。

DSpark 每层 routed experts=128，选 3 个，比主干 384/6 更轻。论文中先在主干预训练后单独训练 DSpark，后训练时继续对齐策略，但不让其目标梯度回传主干。当前公开 minimal generate.py 走普通自回归采样，不能用它直接验证生产投机加速。

视觉 encoder 和 CED encoder 不是同一个东西

vision_config 的 32 层、1024 hidden、16 heads 定义独立 ViT；它把图像转为视觉 embedding，再进入语言模型 40 层。CED encoder 则是语言网络前 20 层。二者名字相似但功能不同。

patch_size=14，downsample_ratio=3 对 3×3 patch 邻域做 pixel-unshuffle，把 9 个位置的通道合并后送入 projector，视觉 token 数减少 9 倍。例如 1344×1344 图像形成 96×96 patches，降采样后为 32×32=1024 个视觉特征位置；特殊分隔或换行 token 需另计。

min_pixels=295936=544² 是预处理面积约束，不表示所有图像都变成 544×544；任意长宽比和对齐逻辑应以 image_processor 为准。位置频率配置也不会独立决定识别能力。

论文 §2.1.1、§2.4.3、§4.2.2；参考实现 DSparkBlock 与视觉配置。

主题论文事实为什么有意义
预训练45T 多模态 tokens；从 64K 长度直接训练稀疏注意力；34T 时扩至 1M；无 dense attention warmup。稀疏检索与长上下文能力经过训练，不能只修改 config 把旧模型变成此结构。
优化器线性矩阵用 Muon，Q/K 用 head-wise Muon；大 embedding / prediction head 用 momentum + Sinkhorn balancing；非矩阵参数用 AdamW。按矩阵结构和状态存储成本选更新规则；不是全模型统一 Adam。
跨层共享训练shadow indexers、流水线共享 payload、micro-batch 生命周期管理。共享组件跨 pipeline stage 后，参数所有权、反向梯度和重计算必须协调。
推理部署视觉编码 / Prefill / Decode 分离；多数 Reuse 层为 15 个 Prefill kernels、11 个 Decode kernels。实际执行靠融合和调度，模块数量不能等同 kernel 数。
后训练沿用 SFT → RL → OPD，主要投入可验证任务合成、环境建设、质量校验和异步 rollout；最终 OPD 使用超过 40 个 teachers。性能提高不只是 attention 架构效果；任务数据和环境反馈也是核心变量。
异步 RL样本粒度补充并发、token 级中断和恢复；限制 off-policy 程度，对过时 token 做 loss mask。减少长尾等待，但样本长度偏差与跨 checkpoint 状态必须显式处理。
推理预算训练时给定 effort 标量，并用 effort 相关的 token 惩罚控制输出长度。改变任务探索成本；不是修改层数或保证固定 token 上限。

阅读 config 的四个层次：字段给结构尺寸 → 前向代码给张量依赖 → kernel/runtime 给物理存储和调度 → benchmark 给特定负载下的实测结果。跨过任何一层直接下性能结论都容易出错。

10 · 用这些问题检查是否理解

为什么 Top-K=512，但缓存仍随 T 增长？

512 限制当前 query 的读取集合；不同 query 将选择不同位置，完整全局条目仍需留存以便未来检索。

第 28 层和第 29 层分别计算什么？

28 为 Reindex：复用 20 的 KV 与 Indexer K，在候选池内重新选择；29 为 Reuse：复用相同 KV 和 28 的 Top-K。二者仍有自己的主 Q、局部 KV 和输出。

为什么 890 字节不乘 2、40、64 或 32？

K=V 共用 latent，无普通 K/V 两份系数；层共享后只计四组全局缓存；64 和 32 分别是主查询和检索查询 heads，历史各自只保存一份共享向量。

为什么 decoder ratio=1 仍然高效？

序列不压缩，但 20 层共享一份缓存，FP4 减少每条字节，稀疏 attention 控制读取，分层索引减少重复搜索。效率不是只靠序列压缩。

只重放 128 tokens，为什么还可以看更久以前的内容？

被截断的是局部 SWA 依赖；已缓存的全局 KV 仍可读取。但缺失的局部传播不能保证被全局支路完全补偿。

为什么不能把 1M × 890 B 作为完整部署预算？

它只覆盖全局 KV 有效载荷，不包含数千亿权重、Engram、SWA、临时激活、投机状态、通信、对齐与多卡复制。

Engram 和 KV Cache 的生命周期有什么不同？

Engram 是所有请求共享的训练参数表；KV 是特定上下文计算产生的运行时状态。N-gram 历史寻址所需的少量输入状态也不等于整张表。

如果 reference code 显存很大，是论文的 890 B 算错了吗？

先看 tensor dtype、是否真实低精度打包、是否按 max_seq_len 预分配以及各 rank 是否复制。参考数值仿真与生产存储格式不同。
