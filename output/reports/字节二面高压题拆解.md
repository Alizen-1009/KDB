# 字节二面高压题拆解

## 说明

这份文档针对你总结的 8 个“字节二面压力面”题目做拆解，目标不是给出论文级最优实现，而是给你一套：

- 面试现场能手撕出来的最小代码
- 能快速口算的 FLOPs / 访存公式
- 能顺着继续回答的追问框架

默认口径：

- 代码优先写成简洁 `PyTorch / Python / CUDA` 伪实现
- 复杂度按大 O 和主导项口算
- 访存默认按 `bf16/fp16 = 2 bytes`，`fp32 = 4 bytes`

## 1. 这轮面试到底在考什么

你列的 8 题表面跨度很大，但底层只在测 4 件事：

1. 你能不能把模型模块从 paper/概念翻译成可执行代码  
2. 你能不能从 `shape -> 参数量 -> FLOPs -> 访存` 一路往下推  
3. 你能不能区分 `compute-bound` 和 `memory-bound`  
4. 你有没有基础 CUDA/kernel/算法功底

所以最稳的答题节奏不是“我背了很多名词”，而是：

> 先写最小正确实现，再说 shape，再说复杂度，最后说访存和优化方向。

## 2. Linear Attention 手撕

### 2.1 最小实现

这里给一版最经典的 feature-map 形式线性注意力。核心思想是把：

`softmax(QK^T)V`

改写成：

`phi(Q) (phi(K)^T V)`

从而把原本对序列长度的二次复杂度改到线性。

```python
import torch
import torch.nn as nn
import torch.nn.functional as F


class LinearAttention(nn.Module):
    def __init__(self, dim, num_heads):
        super().__init__()
        self.dim = dim
        self.num_heads = num_heads
        self.head_dim = dim // num_heads

        self.q_proj = nn.Linear(dim, dim, bias=False)
        self.k_proj = nn.Linear(dim, dim, bias=False)
        self.v_proj = nn.Linear(dim, dim, bias=False)
        self.out_proj = nn.Linear(dim, dim, bias=False)

    def phi(self, x):
        # 常见选择：elu(x) + 1，保证正值
        return F.elu(x) + 1

    def forward(self, x):
        # x: [B, S, D]
        B, S, D = x.shape
        H, Dh = self.num_heads, self.head_dim

        q = self.q_proj(x).view(B, S, H, Dh).transpose(1, 2)  # [B,H,S,Dh]
        k = self.k_proj(x).view(B, S, H, Dh).transpose(1, 2)
        v = self.v_proj(x).view(B, S, H, Dh).transpose(1, 2)

        q = self.phi(q)
        k = self.phi(k)

        # kv: [B, H, Dh, Dh]
        kv = torch.einsum("bhsd,bhse->bhde", k, v)
        # z: [B, H, S, 1]
        z = 1.0 / (torch.einsum("bhsd,bhd->bhs", q, k.sum(dim=2)) + 1e-6)
        # out: [B, H, S, Dh]
        out = torch.einsum("bhsd,bhde,bhs->bhse", q, kv, z)

        out = out.transpose(1, 2).contiguous().view(B, S, D)
        return self.out_proj(out)
```

### 2.2 面试时怎么讲复杂度

标准 `MHA` 的 attention 部分：

- `QK^T`: `O(B * H * S^2 * Dh)`
- `AV`: `O(B * H * S^2 * Dh)`

线性注意力的主项变成：

- `K^T V`: `O(B * H * S * Dh^2)`
- `Q (K^T V)`: `O(B * H * S * Dh^2)`

如果 `Dh << S`，它对长序列更友好。

### 2.3 访存怎么讲

标准 attention 最大的问题是：

- 容易显式或隐式 materialize `S x S` score/prob matrix

线性注意力的优势是：

- 中间状态不再以 `S x S` 规模出现
- 访存更偏 `S * Dh^2`

### 2.4 常见追问

- 为什么线性 attention 不一定全面替代 softmax attention？
- 因为表达能力、归一化方式和稳定性不完全等价。

## 3. MoE 手撕

### 3.1 最小实现

```python
import torch
import torch.nn as nn
import torch.nn.functional as F


class Expert(nn.Module):
    def __init__(self, dim, hidden_dim):
        super().__init__()
        self.fc1 = nn.Linear(dim, hidden_dim)
        self.fc2 = nn.Linear(hidden_dim, dim)

    def forward(self, x):
        return self.fc2(F.gelu(self.fc1(x)))


class SimpleMoE(nn.Module):
    def __init__(self, dim, hidden_dim, num_experts=4, top_k=2):
        super().__init__()
        self.num_experts = num_experts
        self.top_k = top_k
        self.router = nn.Linear(dim, num_experts, bias=False)
        self.experts = nn.ModuleList(
            [Expert(dim, hidden_dim) for _ in range(num_experts)]
        )

    def forward(self, x):
        # x: [B, S, D]
        B, S, D = x.shape
        x_flat = x.view(B * S, D)

        logits = self.router(x_flat)                      # [T, E]
        scores = F.softmax(logits, dim=-1)
        topk_scores, topk_idx = torch.topk(scores, self.top_k, dim=-1)

        out = torch.zeros_like(x_flat)

        for expert_id in range(self.num_experts):
            mask = (topk_idx == expert_id)                # [T, K]
            token_mask = mask.any(dim=-1)                 # [T]
            if not token_mask.any():
                continue

            token_x = x_flat[token_mask]
            expert_out = self.experts[expert_id](token_x)

            # 取该 expert 对应的 gate 权重
            gate = torch.zeros(token_x.size(0), device=x.device)
            selected_topk = topk_idx[token_mask]
            selected_scores = topk_scores[token_mask]
            for i in range(self.top_k):
                gate += (selected_topk[:, i] == expert_id).float() * selected_scores[:, i]

            out[token_mask] += expert_out * gate.unsqueeze(-1)

        return out.view(B, S, D)
```

### 3.2 面试时怎么讲

MoE 的核心不是“很多 MLP 叠一起”，而是：

- router 给每个 token 选 `top-k` 个 expert
- 只激活少数 expert
- 把 `total params` 和 `active params` 解耦

### 3.3 参数量怎么讲

若每个 expert 是两层 MLP：

每个 expert 参数大致：

`2 * D * Hff`

总 expert 参数：

`E * 2 * D * Hff`

再加 router：

`D * E`

### 3.4 访存怎么讲

MoE 的问题不只是参数多，而是：

- 路由导致 token dispatch
- expert 激活非常稀疏
- batch 变碎
- 多卡时经常出现 `all-to-all`

### 3.5 常见追问

- 为什么 MoE 更容易 OOM？
- 因为 expert 参数总量大，dispatch buffer、大量中间状态和负载不均都可能导致局部内存峰值高。

## 4. MHA 手撕

### 4.1 最小实现

```python
import math
import torch
import torch.nn as nn
import torch.nn.functional as F


class MHA(nn.Module):
    def __init__(self, dim, num_heads):
        super().__init__()
        self.dim = dim
        self.num_heads = num_heads
        self.head_dim = dim // num_heads

        self.q_proj = nn.Linear(dim, dim, bias=False)
        self.k_proj = nn.Linear(dim, dim, bias=False)
        self.v_proj = nn.Linear(dim, dim, bias=False)
        self.out_proj = nn.Linear(dim, dim, bias=False)

    def forward(self, x, mask=None):
        # x: [B,S,D]
        B, S, D = x.shape
        H, Dh = self.num_heads, self.head_dim

        q = self.q_proj(x).view(B, S, H, Dh).transpose(1, 2)  # [B,H,S,Dh]
        k = self.k_proj(x).view(B, S, H, Dh).transpose(1, 2)
        v = self.v_proj(x).view(B, S, H, Dh).transpose(1, 2)

        scores = torch.matmul(q, k.transpose(-2, -1)) / math.sqrt(Dh)  # [B,H,S,S]
        if mask is not None:
            scores = scores.masked_fill(mask == 0, float("-inf"))

        attn = F.softmax(scores, dim=-1)
        out = torch.matmul(attn, v)  # [B,H,S,Dh]
        out = out.transpose(1, 2).contiguous().view(B, S, D)
        return self.out_proj(out)
```

### 4.2 参数量手算

标准 MHA 投影层：

- `Wq`: `D x D`
- `Wk`: `D x D`
- `Wv`: `D x D`
- `Wo`: `D x D`

总参数约：

`4D^2`

如果有 bias，再加 `4D`，通常可以忽略。

### 4.3 FLOPs 主导项

- QKV 投影：`3 * B * S * D * D`
- `QK^T`: `B * H * S * S * Dh = B * S^2 * D`
- `AV`: `B * S^2 * D`
- `Wo`: `B * S * D * D`

在长序列时，attention 部分的 `S^2` 很快压过投影。

### 4.4 访存怎么讲

标准 MHA 的痛点：

- `scores` 和 `attn prob` 都是 `B * H * S * S`
- 中间矩阵非常容易把 HBM 压爆

所以 FlashAttention 的核心不是“数学变了”，而是：

- 不显式 materialize 这些大矩阵

## 5. MLA 手撕

### 5.1 先说面试口径

`MLA = Multi-head Latent Attention`。  
它的目标不是改 attention 公式本身，而是：

- 把 KV 缓存压到更小的 latent 空间
- 减少推理时 KV cache 的内存和带宽成本

### 5.2 一个简化实现

下面不是 DeepSeek 官方等价实现，而是一版**足够面试解释**的最小结构：

```python
import math
import torch
import torch.nn as nn
import torch.nn.functional as F


class SimpleMLA(nn.Module):
    def __init__(self, dim, num_heads, latent_dim):
        super().__init__()
        self.dim = dim
        self.num_heads = num_heads
        self.head_dim = dim // num_heads
        self.latent_dim = latent_dim

        self.q_proj = nn.Linear(dim, dim, bias=False)

        # 先把 K/V 压到 latent，再恢复到多头空间
        self.kv_down = nn.Linear(dim, latent_dim, bias=False)
        self.k_up = nn.Linear(latent_dim, dim, bias=False)
        self.v_up = nn.Linear(latent_dim, dim, bias=False)

        self.out_proj = nn.Linear(dim, dim, bias=False)

    def forward(self, x):
        # x: [B,S,D]
        B, S, D = x.shape
        H, Dh = self.num_heads, self.head_dim

        q = self.q_proj(x).view(B, S, H, Dh).transpose(1, 2)   # [B,H,S,Dh]

        z = self.kv_down(x)                                     # [B,S,L]
        k = self.k_up(z).view(B, S, H, Dh).transpose(1, 2)
        v = self.v_up(z).view(B, S, H, Dh).transpose(1, 2)

        scores = torch.matmul(q, k.transpose(-2, -1)) / math.sqrt(Dh)
        attn = F.softmax(scores, dim=-1)
        out = torch.matmul(attn, v)
        out = out.transpose(1, 2).contiguous().view(B, S, D)
        return self.out_proj(out), z   # z 可视作更紧凑的 KV cache 基础
```

### 5.3 这题面试官真正想听什么

不是你能不能复刻官方代码，而是你是否知道：

- 标准 MHA 的 KV cache 大小与 `S * H * Dh` 成正比
- MLA 想办法把 K/V 存到更低秩或更紧凑的 latent 表示
- 推理收益主要体现在 **KV cache 减少** 和 **HBM 带宽减少**

### 5.4 访存怎么讲

标准 MHA 每个 token 的 KV cache 大小约：

`2 * H * Dh * b`

如果 MLA 把 KV 压到 latent dim `L`：

`L * b`

若 `L << 2 * H * Dh`，KV cache 显著减小。

### 5.5 常见追问

- MLA 为什么更适合推理而不是只看训练？
- 因为 decode 阶段天然 memory-bound，KV cache 占用和带宽是第一大账本之一。

## 6. 上面这些模块的访存 / 计算怎么统一口算

### 6.1 一个总框架

任何模块都先拆三件事：

1. 参数量
2. FLOPs
3. 访存量

### 6.2 参数量

看权重矩阵维度，直接乘。

例如线性层：

`Din x Dout`

参数量：

`Din * Dout`

### 6.3 FLOPs

对 matmul，常用近似：

`[M,K] x [K,N] -> [M,N]`

FLOPs 约：

`2 * M * K * N`

面试里有时也会把乘加算成 `MKN` 级，关键是**保持前后一致**。

### 6.4 访存

先粗算：

- 读输入
- 读权重
- 写输出

如果是 attention，再看是否要 materialize 大中间矩阵。

### 6.5 四个模块口算结论

- `MHA`: 计算量在长序列下被 `S^2` 主导，访存痛点是 `S x S`
- `Linear Attention`: 计算和访存更接近线性，但表达能力和数值性质不完全等价
- `MoE`: 参数量很大，但每 token 只激活少数专家；系统痛点主要是路由和通信
- `MLA`: 计算形式仍接近 attention，但主要收益在 KV cache 更小

## 7. DeepSeek-V3 结构伪代码 + 参数量手算 + 推理访存手算

### 7.1 面试时最稳的说法

你不一定要背所有官方超参，但至少要说对 3 件事：

- `DeepSeek-V3` 是 **MoE + MLA** 路线
- 总参数很大，但每 token 激活参数远小于总参数
- 推理访存的主账本不只是参数，还有 KV cache

根据官方技术报告摘要，`DeepSeek-V3` 是：

- `671B total parameters`
- `37B activated per token`

这个数字可以直接作为口头锚点。

### 7.2 结构伪代码

```python
class DeepSeekV3Block(nn.Module):
    def __init__(self, dim, num_heads, latent_dim, num_experts, top_k):
        super().__init__()
        self.attn_norm = nn.RMSNorm(dim)
        self.attn = SimpleMLA(dim, num_heads, latent_dim)

        self.ffn_norm = nn.RMSNorm(dim)
        self.moe = SimpleMoE(dim, hidden_dim=4 * dim,
                             num_experts=num_experts, top_k=top_k)

    def forward(self, x):
        attn_out, latent_kv = self.attn(self.attn_norm(x))
        x = x + attn_out
        x = x + self.moe(self.ffn_norm(x))
        return x, latent_kv


class DeepSeekV3LikeModel(nn.Module):
    def __init__(self, num_layers, dim, num_heads, latent_dim, num_experts, top_k):
        super().__init__()
        self.layers = nn.ModuleList([
            DeepSeekV3Block(dim, num_heads, latent_dim, num_experts, top_k)
            for _ in range(num_layers)
        ])
        self.final_norm = nn.RMSNorm(dim)
        self.lm_head = nn.Linear(dim, vocab_size, bias=False)

    def forward(self, x):
        kv_states = []
        for layer in self.layers:
            x, kv = layer(x)
            kv_states.append(kv)
        return self.lm_head(self.final_norm(x)), kv_states
```

### 7.3 参数量手算框架

参数量分两部分：

#### 1. 激活路径参数

- attention 路径
- router
- top-k expert 中的少数 expert

#### 2. 总参数

- 所有 expert 全算上

所以 MoE 模型常见两套数字：

- `total params`
- `activated params`

这是你面试里一定要主动说出来的。

### 7.4 推理访存手算框架

推理访存至少看三项：

#### 1. 权重读取

每层需要读当前激活路径对应的权重。

Dense 模型大致按：

`activated_params * bytes`

估。

#### 2. KV cache

这是 decode 时最重要的账本之一。  
对标准 MHA：

`B * S * L * 2 * H_kv * D * b`

对 MLA：

近似变成：

`B * S * L * latent_dim * b`

#### 3. 激活与临时 workspace

相对 KV cache 和权重读取，decode 时通常不是第一主导项。

### 7.5 面试时怎么收束

> DeepSeek-V3 这类 MoE+MLA 模型最值得讲的不是“它有多少层”，而是它把两类成本都打掉了一部分：MoE 把 active params 降下来，MLA 把 KV cache 降下来，所以总参数量很大，但每 token 的实际推理成本并没有和 total params 一起线性爆炸。

## 8. 算法题：堆排序

```python
def heapify(arr, n, i):
    largest = i
    l = 2 * i + 1
    r = 2 * i + 2

    if l < n and arr[l] > arr[largest]:
        largest = l
    if r < n and arr[r] > arr[largest]:
        largest = r

    if largest != i:
        arr[i], arr[largest] = arr[largest], arr[i]
        heapify(arr, n, largest)


def heap_sort(arr):
    n = len(arr)

    # build max heap
    for i in range(n // 2 - 1, -1, -1):
        heapify(arr, n, i)

    # extract one by one
    for i in range(n - 1, 0, -1):
        arr[0], arr[i] = arr[i], arr[0]
        heapify(arr, i, 0)
    return arr
```

面试里要顺手说：

- 建堆：`O(n)`
- 每次取顶并下沉：`O(log n)`
- 总复杂度：`O(n log n)`
- 原地排序，额外空间 `O(1)`

## 9. 手撕 reduce 和 reduce 的优化

### 9.1 最朴素版本

```cpp
__global__ void reduce_naive(const float* in, float* out, int n) {
    __shared__ float sdata[256];
    int tid = threadIdx.x;
    int idx = blockIdx.x * blockDim.x + threadIdx.x;

    sdata[tid] = (idx < n) ? in[idx] : 0.0f;
    __syncthreads();

    for (int s = blockDim.x / 2; s > 0; s >>= 1) {
        if (tid < s) {
            sdata[tid] += sdata[tid + s];
        }
        __syncthreads();
    }

    if (tid == 0) out[blockIdx.x] = sdata[0];
}
```

### 9.2 一个更合理的优化版

```cpp
__inline__ __device__ float warp_reduce_sum(float val) {
    for (int offset = 16; offset > 0; offset >>= 1) {
        val += __shfl_down_sync(0xffffffff, val, offset);
    }
    return val;
}

__global__ void reduce_optimized(const float* in, float* out, int n) {
    __shared__ float smem[32];  // up to 1024 threads => 32 warps

    int tid = threadIdx.x;
    int idx = blockIdx.x * blockDim.x + tid;
    int lane = tid & 31;
    int wid = tid >> 5;

    float val = 0.f;
    // grid-stride loop
    for (int i = idx; i < n; i += blockDim.x * gridDim.x) {
        val += in[i];
    }

    // warp reduce
    val = warp_reduce_sum(val);

    // write one value per warp
    if (lane == 0) smem[wid] = val;
    __syncthreads();

    // final reduce by first warp
    val = (tid < (blockDim.x >> 5)) ? smem[lane] : 0.f;
    if (wid == 0) val = warp_reduce_sum(val);

    if (tid == 0) out[blockIdx.x] = val;
}
```

### 9.3 优化点怎么讲

你至少要说出这几个：

- `grid-stride loop`
- warp shuffle 归约
- 减少 shared memory 使用
- 减少同步次数
- block size 选 128/256 往往更稳

### 9.4 常见追问

- 为什么不是直接一个 kernel 出最终结果？
- 因为 block 间无法直接同步，通常需要多轮 reduce，或者 cooperative groups / atomic 等额外机制。
